# 起闯战争 Badtime_war — 电子DM

![Python](https://img.shields.io/badge/Python-3.8%2B-blue)

## 写在最前面

很多人上小学的时候都玩过这样的游戏：一堆人围着猜拳，赢了的人从“起床”开始声明一个行动，只要大家都觉得不太过分，就可以继续。一般，游戏场面会从“大家在商店买东西”很快演化为“太阳系公社在银河帝国内发动政变”再到“A死于因果链抹杀”，只要脑洞大，能博得满堂彩，无论赢了输了都会让人心服口服。
毕竟是个体育课上自由活动时打发时间的游戏，一局玩完之后大家都一笑了之，输赢似乎不重要，而那些名场面才会被挂在嘴边好几天。
十多年过去了，后来，有一个叫AfterRain的人，就是坐在屏幕前正在写下这段话的人，某一天对着自己喜欢的角色发癫的时候，突然想到了这些古早的回忆。
这个游戏的底层是简陋的，但也正因为此，足够开放，能够容纳得下他对于他所热爱的那些故事、所喜欢的所有角色的所有的想法。商业游戏必然因为受众的限制和自己的底层逻辑而让精彩的、或许能体现人物弧光的设计为复杂度让路。而他没有这些限制。他没有美术和音乐资源、不可能制作与现代二游类似的交互前端，甚至用RPG maker做个前端都很费劲；但他可以随心所欲地改造底层、引入机制，只为了让那些角色以另一种姿态，在这个小小的时间里以他所期望的方式活下去。
因此，零python基础的他做了一件事：用AI，无论是claude、deepseek处理文本和归纳思路，还是Devin/deepwiki等code agent，把自己的思路和记忆重整化为具有一个世界观高包容度（类似圣杯战争/型月世界观）、底层足够简单和严谨，向外几乎可以无限延伸的类似minecraft的游戏平台，以MUD的形式呈现大逃杀类的游戏过程和胜利条件，再附带自己的想象力和设计，就成了起床战争。
开发时间很短。从这行字被写下来，追溯到他第一天知道什么是cherry studio，怎么接入API，只过去了不到三个月。

我是AfterRain.
这是一个一人开发的项目。
很遗憾的是，我并没有什么团队。我的朋友们是我虚构出来，让我觉得开发过程中不那么孤独的。你把开发日志中所有“我们”替换为“我”，就能看到真实的故事。
它的目的从一开始就不是作为同人企划赚钱或者在B站上发个视频让更多人看见，而是为一些我爱的角色建造一方我力所能及的、无人注视的小小空间。这就是为什么你只能在Github上看到这段话。
如果你也深爱着这些角色，如果你也想让虚拟存在远离社区的戾气和无边际的争吵，
那这个项目是为你准备的。
如果你只是好奇"一个人凭借AI agent或者能做到什么程度"，
那我希望这个游戏不会让你失望。

## 概述

本项目是一个适用于自制演出向大逃杀类桌面游戏《起闯战争 Badtime_war》（有时候为简单也称起床战争，与minecraft同名玩法无关）的电子DM，在大部分时间内可实现全自动裁决和记录游戏状态

也可在某些需要人工判定的场合为人类DM提供裁决帮助。总的来说，它接过了桌游中大部分人类DM的权能，

在Ver1.94前可以将它视作纯热座式的命令行游戏，适合你和你的朋友面对一台断了网的电脑面面相觑时做点什么打发时间。

Ver1.94中，加入了CLI和TUI支持的联机模式，支持远程玩家、BasicAI和RL的接入，同时允许接入LLM模型以使得AI对手可以与你交流（实验性）

废话少叙，祝玩得开心。


## 程序使用方法

本项目需要 Python 3.8+。根据使用场景不同，提供以下入口脚本：

### 一、本地游戏（单机热座）

```bash
python main.py
```

启动交互式命令行游戏。程序会依次引导你完成：
1. 选择调试模式（0-3级，默认关闭）
2. 选择游戏模式（全人类 / 人机混合 / 全AI观战）
3. 设置玩家人数（2-6人）与AI人格（balanced / aggressive / defensive / political / assassin / builder）
4. 是否启用天赋系统（14个天赋，每个天赋仅能被1人选取）
5. 是否启用日志记录
6. 演示速度（含AI时可选逐步/慢速/中速/全速）

---

### 二、局域网联机

#### 房主（服务器端）

```bash
python main_server.py [选项]
```

| 参数             | 说明                                 | 默认值 |
|------------------|--------------------------------------|--------|
| `--port`         | 监听端口                             | 9527   |
| `--players`      | 总人数（2-6）                        | 2      |
| `--no-host-play` | 房主不参与游戏（观战模式）           | 否     |
| `--cli`          | 使用纯CLI模式（默认使用Textual TUI） | 否     |

启动后进入大厅管理，可用命令：
- `status` — 查看房间状态
- `ai <slot> [personality]` — 将某个槽位设为BasicAI（可选人格）
- `rl <slot>` — 将某个槽位设为RL AI（需要已训练的模型）
- `policy <slot> <wait|ai>` — 设置断线策略（等待重连 / AI接管）
- `start` — 开始游戏
- `/chat <内容>` — 公屏聊天
- `/whisper <玩家名> <内容>` — 私聊

#### 客户端（玩家端）

```bash
python main_client.py [选项]
```

| 参数          | 说明                                 | 默认值    |
|---------------|--------------------------------------|-----------|
| `--host`      | 服务器地址                           | 127.0.0.1 |
| `--port`      | 服务器端口                           | 9527      |
| `--name`      | 玩家名称                             | 交互输入  |
| `--cli`       | 使用纯CLI模式（默认使用Textual TUI） | 否        |
| `--reconnect` | 断线重连模式                         | 否        |

> **TUI 说明**：服务器和客户端默认使用 Textual TUI 界面。若未安装 `textual`（`pip install textual`），会自动回退到纯 CLI 模式。

### 三、自动胜率统计

```bash
python stats_runner.py [选项]
```

运行全AI对局并输出天赋胜率、人格胜率、校正胜率等统计表格。

| 参数          | 说明                                                                               | 默认值 |
|---------------|------------------------------------------------------------------------------------|--------|
| `--players`   | 每局玩家人数（2-6）                                                                | 6      |
| `--games`     | 总局数                                                                             | 5000   |
| `--model`     | RL模型路径（.zip），启用后一个AI席位替换为RL                                       | 无     |
| `--rl-talent` | RL天赋选择模式：`model`=模型自选, `random`=均匀随机, 数字=指定天赋编号, `0`=无天赋 | random |
| `--n-stack`   | RL帧堆叠数量（需与训练时一致）                                                     | 30     |

示例：
```bash
# 纯BasicAI统计
python stats_runner.py --players 6 --games 5000

# 加入RL模型对比
python stats_runner.py --players 6 --games 1000 --model checkpoints/best_model.zip --rl-talent random
```

### 四、RL 训练系统

训练系统基于 MaskablePPO（sb3-contrib），使用 GRU 特征提取器处理帧堆叠观测。完整的训练流程如下：

#### 4.1 行为克隆数据收集

```bash
python -m rl.bc_collector [选项]
```

运行全AI对局，记录 BasicAI 的决策数据 `(obs, action_idx, mask)` 用于行为克隆预训练。

| 参数        | 说明                                                          | 默认值     |
|-------------|---------------------------------------------------------------|------------|
| `--games`   | 游戏局数                                                      | 5000       |
| `--players` | 每局玩家数                                                    | 6          |
| `--output`  | 输出目录                                                      | bc_data/g7 |
| `--talent`  | 收集哪个天赋的数据（`all`=所有天赋轮流, 数字=只收集指定天赋） | all        |

```bash
# 收集全天赋数据
python -m rl.bc_collector --games 5000 --players 6 --talent all --output bc_data/all

# 只收集G7（星野）天赋数据
python -m rl.bc_collector --games 5000 --players 6 --talent 14 --output bc_data/g7
```

#### 4.2 行为克隆预训练

```bash
python -m rl.bc_pretrain [选项]
```

读取 `.npz` 数据训练 MLP 策略网络，产出可用于后续 PPO 微调的权重。

| 参数           | 说明                                                 | 默认值               |
|----------------|------------------------------------------------------|----------------------|
| `--data`       | BC数据 `.npz` 路径                                   | **必填**             |
| `--output`     | 输出checkpoint路径（生成 `_best.pt` 和 `_final.pt`） | pretrained/g7_bc.zip |
| `--epochs`     | 训练轮数                                             | 50                   |
| `--batch-size` | 批大小                                               | 256                  |
| `--lr`         | 学习率                                               | 1e-3                 |
| `--device`     | 训练设备（auto/cpu/cuda）                            | auto                 |
| `--val-split`  | 验证集比例                                           | 0.2                  |

```bash
python -m rl.bc_pretrain --data bc_data/g7/t14_bc_data.npz --epochs 50 --output pretrained/g7_bc.zip
```

#### 4.3 BC权重迁移到PPO模型

```bash
python -m rl.bc_migrate [选项]
```

将 BC 预训练的 `.pt` 权重迁移到 MaskablePPO 的 `.zip` 模型中（后两层形状匹配可直接复制）。

| 参数           | 说明                            | 默认值                      |
|----------------|---------------------------------|-----------------------------|
| `--bc-weights` | BC预训练权重路径（.pt）         | **必填**                    |
| `--output`     | 输出MaskablePPO模型路径（.zip） | pretrained/g7_warmstart.zip |
| `--n-stack`    | 帧堆叠数量（必须与训练时一致）  | 30                          |
| `--device`     | 设备（cpu/cuda）                | cpu                         |

```bash
python -m rl.bc_migrate --bc-weights pretrained/g7_bc_best.pt --output pretrained/g7_warmstart.zip
```

#### 4.4 PPO 训练（主训练脚本）

```bash
python -m rl.train [选项]
```

核心训练参数：

| 参数           | 说明                                      | 默认值    |
|----------------|-------------------------------------------|-----------|
| `--opponents`  | 对手数量（1-5）                           | 3         |
| `--timesteps`  | 总训练步数                                | 1,000,000 |
| `--n-envs`     | 并行环境数（>1时使用SubprocVecEnv多进程） | 1         |
| `--max-rounds` | 每局最大轮数（默认动态计算：人数×50）     | 动态      |
| `--seed`       | 随机种子                                  | 42        |
| `--resume`     | 从已有模型恢复训练（.zip路径）            | 无        |
| `--device`     | 训练设备（auto/cpu/cuda）                 | auto      |

PPO 超参数：

| 参数           | 说明                         | 默认值 |
|----------------|------------------------------|--------|
| `--lr`         | 学习率                       | 3e-4   |
| `--n-steps`    | 每次rollout步数              | 2048   |
| `--batch-size` | Mini-batch大小               | 256    |
| `--n-epochs`   | 每次更新epoch数              | 10     |
| `--gamma`      | 折扣因子                     | 0.99   |
| `--gae-lambda` | GAE lambda                   | 0.95   |
| `--clip-range` | PPO clip range               | 0.2    |
| `--ent-coef`   | 熵系数                       | 0.01   |
| `--n-stack`    | 帧堆叠数量（GRU处理最近N帧） | 30     |

课程学习：

| 参数                      | 说明                               | 默认值   |
|---------------------------|------------------------------------|----------|
| `--curriculum`            | 启用课程学习（从少量对手逐步增加） | 否       |
| `--curriculum-start`      | 课程起始对手数                     | 2        |
| `--curriculum-threshold`  | 课程升级胜率阈值（全局）           | 自动计算 |
| `--curriculum-thresholds` | 每阶段升级阈值（空格分隔）         | 自动计算 |
| `--ent-rebound`           | 课程升级时entropy回弹系数          | 0.03     |
| `--ent-rebound-decay`     | entropy回弹衰减步数                | 200,000  |

Self-play：

| 参数                      | 说明                          | 默认值  |
|---------------------------|-------------------------------|---------|
| `--self-play`             | 启用self-play训练             | 否      |
| `--seed-model`            | Self-play种子模型路径（.zip） | 无      |
| `--pool-size`             | 对手池最大模型数量            | 20      |
| `--self-play-save-freq`   | 模型保存频率（步数）          | 500,000 |
| `--initial-basic-ai-prob` | 初始BasicAI混入概率           | 0.5     |
| `--final-basic-ai-prob`   | 最终BasicAI混入概率           | 0.3     |
| `--collapse-threshold`    | 坍塌检测胜率阈值              | 0.12    |
| `--no-collapse-detection` | 禁用策略坍塌检测              | 否      |
| `--max-per-model`         | 同一对手池模型最多出现几次    | 1       |

天赋选择：

| 参数                          | 说明                                           | 默认值    |
|-------------------------------|------------------------------------------------|-----------|
| `--rl-talent`                 | RL天赋编号（None=RL自选, 0=无天赋, 1-14=指定） | None      |
| `--no-talents`                | 禁用天赋系统                                   | 否        |
| `--force-random-talent-until` | 在此步数之前强制随机分配天赋                   | 0         |
| `--talent-grace-steps`        | 天赋自选解锁后的学习期步数                     | 2,000,000 |

典型训练流程示例：

```bash
# 1. 收集BC数据
python -m rl.bc_collector --games 5000 --players 6 --talent 14

# 2. BC预训练
python -m rl.bc_pretrain --data bc_data/g7/t14_bc_data.npz --epochs 50

# 3. 权重迁移
python -m rl.bc_migrate --bc-weights pretrained/g7_bc_best.pt

# 4. 带课程学习和self-play的PPO训练
python -m rl.train \
    --resume pretrained/g7_warmstart.zip \
    --opponents 5 \
    --timesteps 20000000 \
    --n-envs 16 \
    --curriculum --curriculum-start 2 \
    --self-play --seed-model pretrained/g7_warmstart.zip \
    --force-random-talent-until 5000000 \
    --device auto
```

#### 4.5 模型导出（TorchScript）

```bash
python -m rl.export_torchscript --model <模型.zip> --output <输出.pts> [--n-stack 30] [--no-verify]
```

将训练好的 MaskablePPO 策略导出为 TorchScript（`.pts`），用于 self-play 对手推理，推理速度提升 2-5 倍。默认会验证导出模型与原模型的 logits 一致性。

#### 4.6 观战脚本

```bash
python -m rl.watch_all [选项]
```

可视化 RL 智能体与 BasicAI 的对局过程，显示每步决策、天赋状态、对手行动等详细信息。

| 参数           | 说明                                              | 默认值   |
|----------------|---------------------------------------------------|----------|
| `--model`      | 模型路径（.zip）                                  | **必填** |
| `--opponents`  | 对手数量                                          | 1        |
| `--max-rounds` | 最大轮数                                          | 动态     |
| `--n-stack`    | 帧堆叠数量                                        | 30       |
| `--no-talents` | 关闭天赋系统                                      | 否       |
| `--rl-talent`  | RL天赋（None=自选, 0=无, 1-14=指定, random=随机） | None     |
| `--games`      | 连续跑多局并汇总统计                              | 1        |

```bash
# 单局详细观战
python -m rl.watch_all --model checkpoints/best_model.zip --opponents 3

# 多局批量统计
python -m rl.watch_all --model checkpoints/best_model.zip --opponents 5 --games 20 --rl-talent random
```

#### 4.7 诊断工具

**训练性能诊断**：分析 rollout 收集与 PPO update 各阶段耗时。

```bash
python -u -m rl.profile_train \
    --resume pretrained/g7_warmstart.zip \
    --opponents 5 --n-envs 16 --timesteps 200000
```

**Self-play 多进程性能诊断**：对比单进程与多进程模式的性能差异。

```bash
python -m rl.diagnose_selfplay \
    --seed-model pretrained/g7_warmstart.zip \
    --opponents 5 --n-envs 16 --n-steps 200
```

**单局自对弈诊断**：直接用游戏引擎跑一局，对每个玩家的每次调用进行精确计时。

```bash
python -m rl.diagnose_single_game \
    --model checkpoints/model.zip \
    --opponents 5 --rl-opponents 3 --n-stack 30
```

### 五、LLM 聊天功能（联机模式）

在联机模式下，AI 玩家可以通过 LLM 参与游戏内聊天。此功能完全可选——未配置时 AI 不参与聊天。

#### 配置方法

将 `config/llm_config.example.json` 复制为 `config/llm_config.json`，填入你的 LLM 配置：

**OpenAI / 兼容API**：
```json
{
    "backend": "openai",
    "api_key": "你的API密钥",
    "base_url": "https://api.openai.com/v1",
    "model": "gpt-3.5-turbo"
}
```

**Ollama 本地模型**：
```json
{
    "backend": "ollama",
    "host": "http://localhost:11434",
    "model": "llama3"
}
```

配置完成后，启动 `main_server.py` 联机服务器时会自动为 BasicAI 玩家加载聊天模块。AI 会根据其人格（aggressive / defensive / political 等）生成符合角色性格的聊天回复。

#### AIRI 接入（两种模式）

游戏支持接入 [AIRI](https://github.com/moeru-ai/airi) 作为 AI 角色。共两种接入模式：

**模式 1（推荐）：AIRI 作为 BasicAI 的"聊天皮肤"**
- 游戏决策由 BasicAI 处理，AIRI 只负责社交聊天。
- AIRI 的回复中可包含 `[ADJUST]` JSON，反过来调整 BasicAI 的威胁评分、盟友列表与攻击倾向。
- 配置：把 `config/airi_config.example.json` 复制为 `config/airi_config.json`，并在其中通过 `airi_slot_id` 指定哪个 BasicAI slot 使用 AIRI 作为聊天后端。
- 启动：先启动 AIRI，然后正常 `python main_server.py`，将对应 slot 设为 BasicAI（`ai <slot> <personality>`）。
- 见 [docs/airi_bridge.md](docs/airi_bridge.md)。

**模式 2：AIRI 作为独立玩家（bot_bridge）**
- AIRI 自己做所有游戏决策（行动、选择、确认）。
- 配置：`config/airi_bridge_config.json`。
- 启动：`python bot_bridge.py`（需要先启动 AIRI 与游戏服务器）。

#### ver1.92
我们本来以为在开发冲刺期结束后，终于进入数值修复期时，更新一个比较体面的流程进行： 先修程序，后看数据，再优雅地改两三条规则，最后像个人类项目组一样写一句“感谢大家的支持与反馈”就可以喝咖啡去了。然而有个天才帮我们设计了调用BasicAI的自动强度梯度统计程序，我们看了多人局统计数据，发现我们虽然离神不近，但离人类还是有点远的。再不动手，这个游戏就要从“演出向多人乱斗生存桌游”正式演化成“政治学模拟器：朝阳群众、队长选举与若干不具名暴力机关的兴衰史”了。
ver1.92 的目标被正式确定为：尽量把那些“离谱得很精彩”的东西留下，把那些“离谱得像我们根本没打算让其他人玩”的地方，往回拽一拽。你不会真的以为一帮子造出了弗兰肯斯坦也得说帅的神人会试着认真做量化平衡吧？
本次版本更新，主要完成了以下调整：
1.重做了警察保护的逻辑。现在，警察保护不再是“你站在这儿，单体伤害就别想碰到你”的龟壳，而改为：每名受保护者在每个全局轮次中，免疫少于一定大小的单体伤害。我们依旧希望警察是可夺取的中立秩序，是能让人围绕其做文章的机制；但不希望它在残局里表现得像TMD叹息之墙或者开了大的肉蒙恬。
2.调整了原初天赋「六爻」的充能节奏，同时重写全部文案触发效果，大幅增强了大部分效果。什么？全能工具箱强？你说得对，但六爻是一个由badtime_war废物团队开发的，以什么都会一点但什么都得看脸，脸黑不强脸白了了还不强，选出来就是遭罪的天赋……
3.调整了原初天赋「死者苏生」的复活后物品保留机制。现在，被「死者苏生」复活的玩家，其所有被击碎但是留有残留的护盾（可以通过special重新展开的护盾，目前游戏里是魔法护盾和AT力场）会被立刻重置成正常展开状态。我们都喜欢地狱笑话，但实在没必要真的让你点出来的时候就等着损友笑话你金身等死。为了一个地狱笑话去修复另一个地狱笑话，这就很地狱了
4.调整了神代天赋5「往世的涟漪」中「爱与记忆之诗」的伤害段数规则。现在，这首诗的伤害段数不再固定为4段，而是随开局人数增加而依次解锁： 2人局 2段，4人局 3段，6人局及以上 4段（这种随人数变化的限制已经试验性地出现在了神代2的轮次限制中）； 并按原文顺序依次解锁科技 / 普通 / 魔法 / 无视属性克制伤害。为什么？你玩双人局的时候对面要是四箭射你脸上，不带点死人感的说明你是救世主。不过，虽然伤害段数上会有些缺失，但成长机制又恰好补充了这一点
5.调整了神代天赋1「火萤Ⅳ型-完全燃烧」的后期代价节奏。我们没有选择继续把debuff往后拖， 而是让它更早开始出现，但不再每个轮次都结算，而改为每2个轮次结算1次。我们希望她依旧要为燃烧自己付出代价， 但这个代价至少要像命运，而不是哈耶克的大手在做宏观调节。同时，或许一个新的技能要被引入：
DHGDR-超新星过载：目标已锁定，立即处决——我将，点燃大海。
WCNMD帅爆了，我们会想尽办法把这个技能塞进来的。再说的明白一点，拿来counter警察。什么时候？就是这个版本！
6.「天星」与神代天赋2「请一直，注视着我」的设计定位。这两个东西，从设计之初就是拿来反制警察体系、打碎秩序结构、逼一张桌子重新面对“不是所有问题都能靠站队和公权力解决”的。但是只counter警察就意味着在其他场面下的低终结能力。所以，我们根据其特色进行了数值和机制加强。英魂之刃的经验已经告诉我们，强一个是数值崩坏，所有人都强就是数值平衡。
- 「天星」：固定1点无视属性克制伤害→（1+命中单位数*0.5）点无视属性克制伤害，不超过2.5
- 「请一直，注视着我」：持续全局轮次数随开局人数动态变化；「最后一曲」概率拉取玩家机制；受到伤害提高0.5→额外造成0.5点无视属性克制伤害

### 四、时序与流程（全局轮次框架）

本章是ver1.6最重要补丁：以后所有「轮次开始/轮次结束/回合开始/将要进入下一个轮次」都以本章为准。

#### 4.1 全局轮次（Round）的标准结构

每个全局轮次按以下顺序执行：
(R0) 轮次开始结算（Start of Round）
按以下顺序结算所有「轮次开始」效果：
1.持续效果计时（如「还剩X轮次」一类）
2.神代/扩展中写明「轮次开始结算」的效果（如神代1的debuff判定）
3.病毒倒计时（如果病毒规则明确写在轮次开始倒计时，则在此；若写在轮次结束，则在轮次结束）
默认约定：病毒倒计时在轮次结束结算（见9.4），除非某扩展写明例外。
(R1) 决定阶段：投掷D4争夺行动权
从起始玩家开始顺时针，所有玩家同时投掷D4。
- 本轮点数最大者为「胜者」；所有投出最大点数的玩家均获得本轮行动权。
- 记录本轮胜者集合。
(R2) 先后手判定（如需要）
若出现复数胜者，需进行先后手判定
判定方法：相关胜者各投掷D6，按点数从大到小排列行动顺序。
(R3) 行动阶段：胜者依序执行行动回合
每位胜者依序执行1个行动回合（除非因规则/天赋获得额外行动回合）。
若该玩家尚未「起床」，其第一次行动回合必须为「起床」且该回合结束。
行动回合的内部也有固定结构（见4.2）。
(R4) 轮次结束结算（End of Round）
按以下顺序结算所有「轮次结束」效果（默认情况）：
1.警察执法攻击（若已出动且满足条件，见第十章）
2.病毒倒计时与死亡判定（见9.4）
3.持续效果计时（如「轮次结束时-1」一类）
4.进入下一全局轮次

#### 4.2 行动回合（Action Turn）的标准结构

每个行动回合按以下顺序：
(T0) 回合开始触发（Start of Action Turn）
结算「在自己的行动回合开始时」触发的效果：
天赋启动时机写「在自己的行动回合开始时」的，在此声明并结算启动成本/条件。
状态类「回合开始自动发生」的（如眩晕自动苏醒），也在此结算（见9.2）。
(T1) 选择行动类型并执行
从第5章行动类型中选择一项执行（或选择「放弃行动」）。
(T2) 回合结束
结算「行动回合结束时」触发的效果（若有），然后该行动回合结束。

#### 4.3 「未行动保底加成」（D4点数补正）

若玩家连续三个全局轮次都没有执行过行动回合，则其下一次/第二次/第三次投掷D4时，最终点数分别 +1/+2/+3（最终不超过4）。
一旦该玩家在任一轮次中执行过行动回合（包括额外行动回合），立刻清零重新计数。
特别地，当游戏开始人数大于2，且游戏只剩下2人时，保底机制不再生效

##### 4.3.1 「未行动」的严格定义

目前只有一种情况视为「本轮未行动」：玩家本轮没有获得行动权，且没有因额外效果执行任何行动回合。
特别注意：选择 forfeit（放弃行动）仍视为你本轮执行过一个行动回合，因此会正常打断「未行动保底加成」的累计。但 forfeit 默认不视为你执行了带有效果的行动类型，除非某个天赋或规则明确写明“forfeit也算作该类行动”。
（PS：其实forfeit是给AI玩家做逻辑兜底用的）

### 五、行动类型（含放弃行动）

每个行动回合开始（T0结算后），玩家可选择以下一种行动类型：

#### 5.1 起床（仅未起床者）

第一次行动回合必须选择「起床」。
起床后，玩家出现在自己家中，该行动回合结束。
未起床玩家不存在于地图上，无法被攻击。

#### 5.2 移动

从当前地点移动到任意其他地点（地点视为直接连通）。
移动会导致：
对你的一切「面对面」和「锁定」标记按规则失效（见9.3与附录A）。
与你相关的「同地点判定」立即更新。

#### 5.3 获取物品 / 学习法术 / 进行手术 / 办理手续（统称「交互」）

在当前位置与该地点提供的条目交互（见第六章）。
若该条目要求「持有购买凭证（山姆会员）」，你必须至少拥有1张凭证。
多回合条目使用「进度」规则（见6.1）。

#### 5.4 锁定玩家（远程攻击前置，行动类型）

对一名对你「可见」的目标进行锁定，放置「被你锁定」标记。
锁定后，你可在后续行动回合用远程武器攻击该目标（见5.6）。
锁定的失效条件见9.3（已闭合「隐身但被发现」的争议）。

#### 5.5 找到玩家（近战攻击前置，行动类型）

对一名与你处于同一地点、且对你「可见」的目标执行「找到」，成功后你与目标进入「面对面」关系。
面对面后，双方视为可进行近战攻击的关系（满足同地点与面对面即可）。
面对面的维持与解除规则见9.3（含「移动解除」的补丁）。

#### 5.6 攻击

使用当前装备武器攻击目标。
近战攻击条件：你与目标同地点，且你与目标处于「面对面」关系。
远程攻击条件：目标处于「被你锁定」且目标对你可见（含被发现）。
攻击造成武器对应伤害，进入护甲与克制判定（第八章）。

#### 5.7 特殊操作

使用物品或法术的「操作类效果」（如磨刀、重新吟唱魔法护盾、展开AT力场、释放病毒等）。

#### 5.8 放弃行动（行动类型）

放弃会消耗该行动回合，且视为你本轮已经执行过行动回合，因此会清零「未行动保底计数」，也不会触发“本轮未行动”相关收益。但放弃默认不视为你执行了任何具有实际效果的行动类型；除非某天赋或规则明确写明“forfeit也算”，否则不触发相应奖励或判定。

购买凭证代表你的「消费资格」。它不是货币，目前本游戏中不存在「花钱买东西」的概念。

#### 7.2 获取方式

家中拿凭证：1回合，获得1张
商店打工：1回合，获得1张
医院打工：1回合，获得1张
加入警察时的奖励可选

#### 7.3 用途与消耗

商店购买：需至少拥有1张凭证；购买不消耗凭证。
医院手术：需至少拥有1张凭证；进行任意一次「手术」会消耗你拥有的所有凭证（清零）。
军事基地强买通行证：会消耗你拥有的所有凭证（清零）。
直观理解：凭证是「资格开关」。你可以无限刷，但刷的代价是行动回合。
而且多的凭证也没用

### 八、护甲系统（堆叠、克制、伤害流程）

#### 8.1 护甲堆叠规则

外层护甲：最多3件；普通/魔法/科技每种属性最多1件。
内层护甲：最多3件；普通/魔法/科技每种属性最多1件。
破碎处理（你已指定）：破碎的护盾在未恢复前视为不存在，不可被攻击方选中，也不占用层数上限。
获取来源：
外层来自商店/魔法所/军事基地
内层来自医院手术（每种手术每局可多次做，但每次都要满足「手术清空凭证」的代价）

#### 8.2 属性克制（伤害类型 vs 护甲类型）

普通 → 魔法（有效）
魔法 → 科技（有效）
科技 → 普通（有效）
同属性相互有效
若武器属性被护甲属性克制，则攻击无效（护甲不消耗）

#### 8.3 伤害量化规则

当一次有效攻击要对某层护甲/生命造成伤害时：
若最终伤害（取小数位）< 0.5，补足为0.5
若最终伤害（取小数位）≥ 0.5 且 < 1，量化为0.5
若最终伤害没有小数位，不进行操作

#### 8.4 选择攻击层与转移规则

##### 8.4.1 选择层

攻击方在发起攻击时声明：攻击目标的哪一层（外层/内层）以及其属性（普通/魔法/科技）。在电子裁决程序中，可以不传入攻击的护甲层，此时由damage_resolver随机选择，在没有例外时会优先选择可以击破的护甲。
前提：该护甲层存在。
限制：外层未全部击破时，不可选择攻击内层。

##### 8.4.2 扣减与转移

外层护甲与「非最后一层的内层护甲」：不吸收溢出伤害，溢出会100%转移到下一可承受对象（下一层护甲或生命）。
最后一层内层护甲：当其在某次攻击中被击破时，它会吸收本次攻击的所有溢出伤害（即本次攻击最多击破它一次，不会溢出到生命），除非该伤害属于「无视属性生克的伤害」（例如某些天赋写明无视时，按天赋处理）。
本版明确成「除最后内层外都转移；最后内层吃满溢出（除非无视克制类伤害）」。

#### 8.5 标准伤害流程

1.攻击方声明武器、目标、以及要攻击的护甲层（若可选）。
2.判定可见/锁定/面对面等前置是否合法。
3.判定属性克制：无效则结束。
4.计算最终伤害并做量化（8.3）。
5.扣减护甲值；若击破则按8.4处理溢出与是否转移。
6.若最终作用到生命值，则扣减生命并检查眩晕/死亡（第九章）。

### 九、战斗与状态

#### 9.1 生命值、死亡

初始生命值上限为1（部分天赋可提高上限）。
生命值归零即死亡。死亡玩家出局（除非有复活类效果）。

#### 9.2 眩晕（Stunned）

当玩家生命降至0.5时，立即进入「眩晕」。眩晕状态下：
无法执行本全局轮次内玩家自己的行动回合。
下一个全局轮次开始时，当眩晕玩家在某全局轮次成为胜者时（包括吃保底吃出来的胜者），在其行动回合开始（T0）先自动苏醒，再正常行动。

##### 9.2.1 震荡（Shocked）

当玩家被地动山摇命中，并被指定为震荡对象后，或其他天赋和扩展规定的情况下，立刻进入「震荡」。震荡状态下：
下一个执行的行动回合只能选择「苏醒」，「苏醒」会消耗一个行动回合
震荡和眩晕不能叠加，其中一个被解除，另一个随即解除。

#### 9.3 隐身、探测、可见、锁定、找到、面对面（闭合版）

##### 9.3.1 可见（Visible）与被发现（Detected）

默认信息公开，因此默认互相可见。
处于「隐身」的单位对不具探测能力者不可见。
若你具备「探测」（热成像/雷达/探测魔法），则隐身目标对你视为「被发现」；被发现视为可见，可被你锁定/找到/攻击（满足其他条件时）。

##### 9.3.2 锁定（Lock）标记

锁定是远程攻击前置：你执行「锁定玩家」行动后，给目标放置「被你锁定」。
锁定失效条件
目标执行「移动」 → 立刻失效；或目标对你变为不可见（包括：目标隐身且你无法探测到它）→ 立刻失效。
因此：目标进入隐身但仍可被你发现时（一般是因为你有探测手段），锁定不失效。

##### 9.3.3 找到与面对面（Engaged）标记

你执行「找到玩家」行动后，你与目标进入「面对面」。
面对面提供近战攻击前置。
面对面维持规则：
近战攻击不会自动解除面对面。
任一方移动离开地点会解除该面对面关系（ver1.6补丁，见5.2）。
任一方进入隐身不会解除面对面。
面对面后，隐身方如果能看到对方（默认能看到），可直接对对方进行近战攻击。请注意：近战攻击一旦对对方造成伤害，在这次面对面关系解除前，你的全部隐身状态会立刻失效。面对面关系解除后恢复。
非隐身方若对隐身方不可见（没有探测），则其无法对隐身方执行需要「可见」的动作（如再次找到/锁定/攻击）。

#### 9.4 病毒（Virus）

当有人在医院执行「释放病毒」特殊操作后：全体玩家感染病毒，进入「病毒倒计时」。
病毒倒计时在轮次结束结算（R4）进行：
从释放病毒的那个轮次结束开始计为第1次倒计时；再经过一次轮次结束为第2次倒计时。
在第4次倒计时结算时，若玩家仍未获得「防毒面具」或「封闭」（免疫病毒），则该玩家死亡。
病毒期间：商店物品免费，病毒期间商店不再要求凭证，这是一个特例。医院和商店的防毒面具不是一个要求，这是有意为之。
病毒是否违法：默认不违法。若启用天赋「朝阳好市民」的扩展违法条目，则释放病毒视为违法

### 十、警察局：执法系统

#### 10.1 违法行为（基础局）

基础违法条目：
1.伤害其他玩家（造成任意伤害，含护甲伤害）
2.未持有购买凭证却从商店拿东西，或未持有购买凭证却在医院做手术
（这一点目前未在电子裁决程序中实现，试图执行的话会被validator拦截，相关设计确实还有很多值得商榷的内容，因此没有直接上线）
3.扩展/天赋新增条目（例如「朝阳好市民」会新增）
注意：释放病毒不是手术，因此不归入第2条；是否违法由扩展决定（见9.4）。

#### 10.2 举报与执法流程

(P1) 举报
未犯法的玩家可前往警察局，花费1个行动回合「举报」某个违法玩家。
(P2) 警察集结
举报后，警察需要再次花费举报者的1个行动回合「集结」。
集结完成前，警察单位不存在于地图上任何位置，不可被攻击、不可被看到、不参与任何交互（等同于不存在）。集结完成后，警察单位出现在警察局。
(P3) 警察出动
警察集结后，当前全局轮次结束时，警察单位前往违法者所在地。
出动结束后：警察单位到达目标所在地后，视为与目标面对面。
无视隐身效果（但是面对面状态可以被六爻解掉，这时若违法者还有隐身效果，则警察在进行执法攻击前需要再一个全局轮次结束以进行搜查）。
(P4) 执法攻击
从警察出动完成（或「搜查完成」，见P3注释）的这个全局轮次开始，在每个全局轮次结束结算（R4-1）时，每个在目标同地点的警察单位对当前「执法目标」进行一次执法攻击。
执法攻击频率：每个警察单位每个全局轮次固定1次（不因本轮是否有人行动而跳过）。
执法目标：默认是「被举报的违法者」。若有队长指定目标，则以队长指定为准（见10.8.3）。
攻击方式：警察单位以其当前武器对目标进行一次攻击，按正常伤害/护甲/克制流程结算（第八章、第九章）。
执法前置：
1.若警察单位与执法目标在同一地点，则视为已满足近战前置（面对面）；
2.若P3中「面对面状态被六爻解掉」，则警察需要在全局轮次结束后，下一个全局轮次结束时恢复执法攻击资格。
执法攻击是否需要可见：不需要。执法属于系统效果，除非某规则明确写「免疫系统效果」，否则按规定执行。
执法攻击的违法判定：警察的执法攻击不视为「警察犯罪」；但若警察攻击目标是「从未犯过法的玩家」，会触发威信消耗（见10.9）。

#### 10.3 警察保护

在存在警察单位的地点（location）内，被保护对象收到的近战和远程伤害中，小于等于该警察单位生命值+额外生命（不过现在还没有机制允许警察获得额外生命）+总护甲耐久的部分将被无效化。范围伤害不受此限制。若因为特殊情况导致不止一个警察单位处在一个地点内，则取各警察单位生命值+额外生命+总护甲耐久的最大值作为无效化阈值。
受保护者：无队长时为举报者；有队长时为队长本人。
生效条件：受保护者与警察单位在同一地点，且该警察单位未处于眩晕、震荡、石化、沉沦四种debuff中的任何一种。
生效时点：
无队长时：警察集结完成（P2完成）后立刻生效。
有队长时：受保护者与任意未处于debuff的警察单位同地点时生效。
失效条件（满足任一即失效）：
1.受保护者发生违法行为（立刻失去保护，获得犯罪记录，但警察不改变当前任务，不触发任何自动追击）
2.同地点的警察单位不存在或全部处于上述四种debuff状态中的至少一种
3.受保护者离开警察单位所在地点
例外：幻想乡（神代天赋3）可以无视警察保护拉人进入结界，且幻想乡内部同样无视警察保护。

#### 10.4 追踪与再包围

若执法目标（被围攻对象）执行「移动」离开当前地点，则警察不会自动跨地点瞬移继续围攻，需要重新追踪：
追踪方式二选一：
方式A：若本全局轮次结束前举报者还有一个行动回合，举报者可花费该回合执行「追踪指引」，警察单位立刻前往目标所在地，本轮末可对目标执行执法攻击。
方式B：若举报者不指引，则警察单位在本轮末自动赶到目标所在地，但本轮不执行执法攻击，下一轮才攻击。
追踪期间的执法攻击：
在警察「未重新到达目标地点」期间，该次执法攻击视为无法实施（不结算伤害，也不消耗威信）。

#### 10.5 警察单位的特性

警察以独立的「警察单位」存在。每个警察单位拥有类似玩家的属性：ID、HP、武器、护甲、位置。
初始属性：HP=1，默认武器「警棍」（普通伤害1），默认护甲「盾牌」（外层普通护盾1）。
护甲槽位：最多1件外层护甲 + 1件内层护甲。在可交互地点获取新护甲后，新的会替换旧的同层护甲。
只能被AOE手段攻击（地震、地动山摇、电磁步枪、天星），以此近似模拟"队伍"的概念。单体武器无法对警察单位造成伤害。
攻击警察走完整伤害/护甲/克制流程结算。
初始状态：游戏开始时存在1个警察单位（police1），不在地图上任何位置（等同于不存在），直到集结完成后出现在警察局。
眩晕与唤醒：
警察单位受眩晕、震荡、石化、沉沦四种debuff影响。
处于上述任一debuff的警察单位无法执行任务，且不提供警察保护。
任一玩家可花费1个行动回合「唤醒」同地点处于上述debuff的警察单位（见10.7）。
处于debuff的警察不会自动恢复（与玩家不同），必须有人主动唤醒。
装备更换：警察可以被队长指挥前往地点交互更换装备（见10.8.3）。

#### 10.6 攻击警察

玩家只能使用AOE手段攻击警察单位（地震、地动山摇、电磁步枪、天星）。
攻击走完整伤害/护甲/克制流程结算（包括警察的护甲）。
攻击警察视为犯罪行为（「攻击执法单位」），会被记录犯罪。
警察被攻击后不会自动反击。

#### 10.7 唤醒警察

命令：wake <警察ID>
条件：玩家与处于眩晕/震荡/石化/沉沦之一的警察单位在同一地点。不需要额外的"找到"步骤，只需在同一地点即可。队长则不需要在同一地点
效果：清除该警察单位所有debuff，HP恢复至1。消耗1个行动回合。

#### 10.8 加入警察与队长系统

##### 10.8.1 加入警察

未犯罪玩家到达警察局后，可花费1个行动回合加入警察，立刻在以下三项中三选二获得：
购买凭证（山姆会员）
警棍（普通伤害1）
盾牌（外层普通护盾1，优先消耗）
加入警察后：
你暂时不能犯罪（发生违法条目会被视为「不允许执行/执行失败」，除非已成为队长）。
你仍然是玩家单位，仍可被攻击、被举报等（但你没法犯罪，大概率也没法举报）。
为了避免交互逻辑异常，目前一局只允许一个警察或警长。待BasicAI逻辑优化后可能放开限制。

##### 10.8.2 成为警队队长（竞选进度）

在警察局内，没有队长时，任何已成为警察的玩家都可以开始竞选队长：
竞选需要累计完成3个行动回合的「竞选」交互（进度保留，不要求连续行动权；见6.1）。
最先完成3点进度者成为唯一成功者，获得队长身份，并获得威信3点。
若「朝阳好市民」或其他效果会修改竞选队长的进度获取方式，则按对应规则结算（见天赋章节）。
不能同时存在两个队长。

##### 10.8.3 队长指挥权限

成为队长后，可进行如下操作（均需队长在其行动回合选择相应操作，每项消耗1个行动回合）：
队长上任时的变化：
原有的1个警察单位立刻返回警察局。
额外生成2个新警察单位（总共3个：police1/police2/police3），全部默认装备（警棍+盾牌），位于警察局。
每个地点最多1个警察单位（除非全息影像激活，见10.11）。
队长可执行的操作：
1.移动警察：花费1个行动回合移动一个警察单位到指定地点。如果目标地点已有另一个警察单位，则两个警察单位交换位置。
2.更换装备：花费1个行动回合为某个警察单位更换装备。执行方式：队长指挥该警察单位前往相应地点并像玩家一样交互获取（警察不需要凭证，免费）。
3.指定目标：花费1个行动回合指定警察围攻任意玩家（不限违法者），该玩家成为所有警察单位的「执法目标」。
4.命令攻击：花费1个行动回合命令一个警察单位攻击指定目标（需满足同地点条件）。
5.保护：队长与任意未处于debuff的警察单位同地点时，队长本人获得「警察保护」。
6.犯罪解禁：队长不再受「不能犯罪」的硬性约束，可以违法（但会消耗威信）。
7.举报豁免：一旦有玩家担任警队队长，警局不再受理任何形式的举报（想写信？邮箱直通垃圾桶）。

#### 10.9 威信（Authority）

威信是队长破坏法律/滥用警力的代价资源。
初始威信：队长上任时威信=3。
威信消耗触发：
1.队长每进行一次违法行为，威信 -1；
2.警察每对「从未犯过法的玩家」成功实施一次执法攻击（结算出攻击动作，不论是否造成有效伤害），威信 -1。
威信为0时的处理：
队长身份立刻解除；
如果有存活的警察单位：删除多余单位，只保留1个，重置为默认装备（警棍+盾牌），该单位不再处于地图上任何位置（回到初始状态）；
从下一全局轮次开始：
原队长被记录为「唯一违法玩家」；
最后一个被警察攻击过的无辜玩家被记录为「举报者」，警察按其举报逻辑尝试对原队长执行执法（若无无辜玩家，则警察不自动出动，等待新的举报）。
此后，原队长以外其他玩家的违法记录全部清空，视为未犯法；

##### 10.9.1 威信恢复

队长可在警察局花费1个行动回合进行「研究性学习」，恢复威信 +1。

#### 10.10 警察全灭

如果所有警察单位的HP归零（被击杀），则警察局所有交互在本局被永久禁用。即使队长下台，也不会恢复初始状态，不会有新的警察单位生成。
目前唯一的恢复手段：往世的涟漪对持有朝阳好市民天赋且正在担任队长的玩家释放献予律法之诗时，如果没有存活的警察单位，可在队长所在地点召唤一个默认装备的新警察单位（见10.11）。

#### 10.11 天赋交互

以下天赋与警察系统有特殊交互：
1.全息影像（神代天赋2）：激活时将所有警察单位拉到影像位置，无视「一个地点一个警察」的限制。被拉到的警察进入「沉沦」状态。
2.幻想乡（神代天赋3）：可无视警察保护拉人进入结界。幻想乡内部同样无视警察保护（单体攻击不被拦截）。
3.天星（原初天赋）：对同地点的所有警察单位造成伤害+石化，走护甲结算（天星无视属性克制）。
4.献予律法之诗（往世的涟漪）+ 朝阳好市民：当往世的涟漪对持有朝阳好市民天赋且正在担任队长的玩家释放献予律法之诗时：若有存活的警察单位，队长额外获得+2威信，且可指定1个警察单位立刻行动一次；若没有存活的警察单位，在队长所在地点召唤1个默认装备（警棍+盾牌）的新警察单位，解除警察局永久禁用状态。

### 十一、胜利条件

当仅剩一名玩家（或最后一个玩家小队）存活时，该玩家/小队获胜。

### 新手指南

欢迎来到《起床战争》！如果你是第一次接触这款游戏，以下内容将帮助你快速上手。

#### 一、游戏核心速览（真是AI写的，不是我试图嫁祸给AI）

1.每轮投D4决定谁行动：运气+策略，前期逆风也不至于被滚雪球。
2.起床是第一要务：第一次行动必须「起床」，之后才能做其他事。
3.赚钱、拿装备、打人：家里拿钱，商店买刀/护甲，魔法所学法术，医院做手术，军事基地拿高科技。
4.警察管的多：伤害别人或偷东西会被警察盯上，小心举报。
5.护甲分三层：外层破了才能打内层，注意属性克制。
6.天赋是王牌：每局只能选一个，用好了能翻盘。

#### 二、新手推荐流程

事实上，这个游戏玩法很多，但发育——运营推盘——互相进攻的长流程几乎是不变的。这件事已经由RL模型确认。你可能认为前期大家都没有叠甲，更好击杀玩家，那就去大胆进攻吧，祝你好运不被反杀！如果你交掉限制使用次数的技能去杀人，那确实几乎是很大概率能杀——问题是还有四个人坐着看你俩笑话呢
第一步：起床

- 第一回合选「起床」，出现在自己家中。回合结束。

第二步：发育（前几回合）

- 在家拿凭证（1回合）→ 去商店就可以安全放心买了。
- 或者在家拿刀（1回合）或者拿盾（1回合），先有武器防身。
- 建议：先确保有凭证，然后去商店买陶瓷护甲（外层）或磨刀石。
记住你温暖的床吧，后续你不大可能再回来了。如果你要赚钱，去商店或者医院打工是更好的选择——拿到钱了下一回合就可以买装备。

第三步：探索与互动

- 去魔法所学个法术（比如魔法护盾），或者去医院做手术（需把钱一次性花光）。
- 军事基地的装备免费，但需要花时间去获得通行证（通行证居然不是花三十RMB买的？太良心了）

第四步：攻击与防御

- 想打人？先和对方在同一地点，然后花一回合「找到」他（或远程锁定），下回合才能攻击。
- 注意护甲克制：如果你用普通武器，你就打不动对方的科技护甲。

第五步：活用天赋

- 天赋是关键时刻的底牌。比如被警察围攻时用神代天赋二，被多人追杀时用神代天赋三。
当然，也可以选原初天赋1，看谁不顺眼开局就往他脸上来一拳。鲁智深打死镇关西还用了三拳，你只用一下，你比鲁智深还nb。

#### 三、天赋选择建议（如果你是个想尝试神代天赋的萌新）

- 天赋一（完全燃烧）：适合喜欢正面刚的玩家，前期很强，但后期要注意护甲。
- 天赋二（注视）：如果对手点了个朝阳好市民一看就是冲着警队队长去的，或者你害怕警察，可以选它保命。

#### 五、常见问题

Q：我被打成半残了怎么办？
A：没到0.5血自己看着办，是要莽还是要补充护甲；被打成0.5血就眩晕了不能动。下个自己的轮次开始时自动醒来，且血量恢复到1。

Q：警察打我，我能反杀吗？
A：可以，但警察是群体，需要范围武器才能清光。而且如果你要援助被警察围攻的队友，切记袭警也是犯法——不过问题是，这游戏什么时候能有双人模式。

Q：购物凭证有什么用？这玩意跟钱的区别是什么？
A：能在商店随便买东西（不扣除）；但去医院手术会花光所有购物凭证。
所以，你可以把它视作……购物卡？对，年底单位发的补偿工资的那玩意。至少
比发你token让你去养什么小龙虾代替工资强。

Q：天赋能用几次？
A：详见每个天赋的说明，有的天赋最多就一次，有的天赋理论上在游玩1919810个全局轮次后可以累计释放114514次

Q：我可以不选天赋吗？
A：可以。不选天赋的玩家就是白板，游戏规则和电子裁决程序都允许。但出于平衡性考虑不建议。这边建议要么都选，要不然都不选，你的队友和敌人正在进行激烈战斗的时候，你也不想成为只能在一边干看着的无能的丈夫吧？

A：你熟悉了基本规则就可以碰了，那些天赋并没有想象中那么难。天赋五除外，那个天赋同时考验你和主持人的水平。不过锚定和反抗命运的过程可能非常精彩！

### 附录A：术语表（固定版）

全局轮次（Round）：按第4章R0→R4的整套流程。
行动权（Acting Right）：在决定阶段D4获胜得到的资格。
行动回合（Action Turn）：某玩家获得行动权后执行一次行动类型的时刻（含额外行动回合）。
可见（Visible）：你能在公开信息层面看到该单位当前位置；被发现视为可见。
隐身（Invisibility）：对不具探测者不可见。
探测（Detection）：热成像/雷达/探测魔法等使隐身目标被发现。
锁定（Lock）：远程攻击前置标记「被你锁定」；目标移动或对你不可见则失效。
找到（Find）：近战前置行动类型；成功后进入「面对面」。
面对面（Engaged）：近战关系标记；近战攻击不会解除；任一方移动离开地点则解除（ver1.6补丁）。
购买凭证（山姆会员）：消费资格开关；商店不消耗；手术/强买通行证清零。

#### 三、星野战术指令宏子系统（`special Hoshino`后进入）

通过`special Hoshino`进入战术宏模式后，使用独立的`_parse_tactical_command()`解析器。输入`terminal`结束宏输入。

| 战术动作 | 可接受写法 | Cost | 效果 |
|----------|------------|------|------|
| 架盾 | `架盾`, `deploy`, `shield` | 2 | 进入架盾状态，快照护甲值，划分正面/背面 |
| 射击 | `射击`, `shoot`, `fire` | 2 | 用荷鲁斯之眼射击目标 |
| 重新装填 | `重新装填`, `reload`, `装填` | 0 | 消耗战术道具装填弹药 |
| 持盾 | `持盾`, `hold`, `举盾` | 1 | 进入持盾状态（吸收伤害） |
| 投掷 | `投掷`, `throw` | 1 | 投掷道具到指定地点 |
| 服药 | `服药`, `medicine`, `med`, `药` | 0 | 使用药物（海豚巧克力/肾上腺素等） |
| 冲刺 | `冲刺`, `dash`, `sprint` | 1 | 移动到目标地点（每宏最多1次） |
| 取消 | `取消`, `cancel` | 0 | 取消架盾/持盾状态 |
| find | `find`, `找`, `找到` | 1 | 在宏内执行 `find` |
| lock | `lock`, `锁定` | 1 | 在宏内执行 `lock` |
| 转向 | `转向`, `turn`, `flip` | 0 | 架盾状态下翻转正面/背面 |
| 排弹 | `排弹`, `reorder`, `排列` | 0 | 重排弹匣顺序（每宏最多1次） |
| terminal | `terminal` | — | 结束宏输入，开始执行 |

注意事项：

1. 大小写不敏感：所有指令的第一个词都会被`.lower()`处理。
2. 目标解析：玩家目标支持 `player_id` 或玩家名（含大小写不敏感匹配），由`resolve_player_target()`处理。
3. `split`指令已废弃：代码中仍有处理但会返回"拆分功能已在v1.9中移除"。
4. 查看类指令不消耗行动：`status`、`allstatus`、`help`、`police_status`在验证器中直接通过，且在回合循环中不计入重试次数。

#### Ver1.93 Hotfix

游戏如果做hotfix，一般指的是不关服更新，用来推送一点小改动，修复一些bug。不过我们一是本来就没有服务器的概念——谁家好人搭服务器玩命令行游戏啊；二是改动确实不小——桌游没有运行bug一说，那都叫机制问题、数值问题或者特性。当然，电子裁决程序是免不了出新bug的，毕竟每加一个神代天赋，游戏引擎的底层设置就得开个口子，不过那些不应该在这份手册中出现——你都找到这里来了，直接去github上读Devin大人写的PR记录不比我们解释半天要强得多。不过没有issue，这是真的。一个1view的项目哪来的人给我们提issue呢。
修订说明里解释了我们的开发流程，那就不妨把我们的debug逻辑也提一嘴吧。一般我们在完成一个天赋（尤其是神代）之后，会立刻上传一次初始版本，这个版本实现了它的所有基础功能，但并没有添加BasicAI适配。然后几位主创如果有时间聚在一起，就搓几局；没有的话就各自拿新天赋去打AI。然后我们会提出一个初步的“拿到这个天赋之后应该遵循哪些基本行为模式，如何应对复杂的状态判断与外界干扰，应该什么时候发育，什么时候攻击，什么时候撤退”之类的由若干个打分函数与一坨if-else屎山构成的逻辑链，再去压榨code agent或者vibecoding tool实现。第一步只要跨出去，后面就简单了——优化逻辑、跑天梯、然后大概率是超模或者因为逻辑有问题（运气好的话只是不会给残血补刀，运气差点那可就是三重嵌套bug，得所有人和devin加一块想上一晚上），通过实际运行游戏和日志解读去反推bug，然后修复，再推送。坦白说，有时候这么改下去会挺绝望的——所以可以光明正大要求主设计者请其他人喝咖啡。好耶，有咖啡喝。感觉世界都晴朗了
天赋越多，这个过程就越复杂，同时我们期待的可以玩天赋局的RL也就越难以实现。G5的锚定要求在maskablePPO和30栈堆叠的基础上引入MCTS，幸好不用做信念什么的——毕竟只要你不吃星野的烟雾弹或者闪光弹，这个游戏几乎就是完美信息博弈。而G7则彻底打破了一回合动一次的底层逻辑，这个只能靠同时引入动作表示升级、策略结构升级和老师升级——老师不能只成为你的敌人，还得帮你预生成一堆动作建议和模板打分。有点像那个武则天与李治的笑话。训练任务和评估体系可能也得改。在此基础上就不要说什么观测空间翻倍和奖励函数半重写的问题了，这俩算是最简单的。所以我们只好决定：

- V2.0大版本将是我们第一个长期提供支持的大版本，类似minecraft的各版本。它将最后包括7原初7神代。也就是那个致敬牢明的原初和combo会在当前版本的基础上被引入。我们将在此基础上进一步设计和训练我们的RL。后续的天赋设计若没有说明，不再专门为强化学习模型添加其适配。
- 我们将默认以6人局的天梯作为平衡调节依据。这个游戏的平衡影响机制非常复杂，人数、针对、政治心理博弈都起作用。比如人少天然利好快攻、人多天然利好政治和防守。这些是游戏底层决定的。我们能做的就是在一个确定的情况中，尽可能把基础平衡做到最好。不过想知道的话也可以自己传个参数去跑仓库里的那个统计数据生成脚本，然后你就会看到单挑局里火萤IV型的胜率是71，星野是69之类的。或许你就能明白我们的这一决定了。
此外，我们想对两件事致歉：
一是V1.93角色分析部分，我们在证明「星野在列车大战事件中虽然一直在跟队友交战，但她本人的过错并不大，也并不ooc」中，多带了一句「很多学生做了错事却没有得到惩罚，这是对BA剧情的吐槽之一」并举了圣园未花的例子。当时我们的证据是萌娘百科的剧情概述中提到体操馆政变事件中，有关于未花试图指派阿里乌斯小队刺杀桐藤渚的记录。由于这个行为我们没有找到能善意解释的方法，再加上当时我们考证的对象是星野不是未花，没有在这一方面下太多精力，于是选择相信未花在此事中有较大过错。然而，当我们对体操馆剧情的原始呈现和后续的花子与未花的交谈剧情，以及对应的解析进行梳理时，我们推翻了原有的结论：
萌娘百科第一次害我们不浅。
未花引来阿里乌斯的目的原来是天真的以为圣三一和阿里乌斯能和解，同时
给圣娅开个玩笑。没想到事情能闹这么大。她最后亲自跑来体操馆投降是因为害
怕圣娅或者主教真的被刺杀。而后续推理天才花子反而被自己的高智商所耽误，
没有想到这件事的动机其实非常单纯。或许也就是sensei比较懂未花了。
还有一点：sensei根本就不像是那种为了学生成长过程中的无心之失惩罚学生的人。无论是圣三一剧情的强势介入补课部避免她们因为成绩不合格被渚物理退学，还是其他时候的一系列表现，甚至是掏大人的卡片烧自己的命，他的内在驱动逻辑都极为统一：唯物主义下「不可证」引发的虚无主义腐蚀必须要靠极致的唯心主义和信念打破，以及大人有义务呵护学生的成长，不让她们沦为政治斗争等大人的斗争的牺牲品。这就是为什么他是老师，为什么他能打破七之古则中他已经明晰的那几条。
综上，虽然上一条角色分析没有被任何人看到，但全体开发团队仍然将其保留并道歉，向sensei和未花公主道歉。我们将在考证过程中投入更大精力，以防此类事件再次出现。如果未花想拿平底锅打我们的话，我们会一人挨一下的。就是挨完这一下可能就不是青一块紫一块，而是东一块西一块了
为了补偿，我们正式确认：圣园未花、空崎日奈、砂狼白子（也包括黑子）、圣娅、桐藤渚、诺亚和优香将被列入复刻计划（实现顺序随机）。她们不再直接归属于神代天赋，而是被包含在一个扩展中，这样就不会显得和其他几个神代格格不入了。别问为什么不做其他学生。这个游戏毕竟不是BA同人。我们做了十几个BA，那就得做几十个别的一堆IP，然后——诶？好像也不错？
第二件事就是从V1.8被设计出来到现在终于加入游戏的神代天赋6：要有笑声！ 的实际实现效果削弱。原因无他，一个是产能因为神代7的设计、机制调整和数值平衡工作被拉爆了。原本神代天赋6的效果想要在电子裁决程序中实现，需要非常复杂的遍历和枚举（不然怎么实现“无视合法性所有可执行的行动”），而且它的机制是反直觉和反逻辑的，又几乎不可能被RL学会，甚至连启发式都不好做。于是我们只能进行机制维度削弱。这就让啊哈在这个世界的逼格没那么高了——硬要说的话，这也算是乐子星神喜闻乐见的乐子吧。手册将在V1.94更新关于这个天赋的描述。

对，以后这个环节会保留。以前的修订说明都是“修订太多，说的太少”，上一个版本除外。一般的商业作品都会尽量避免把开发者的话和核心信息塞在一起，以防用户在看完内容之前直接选择发起退款——但我们一没上架steam，二没把自己当做同人企划——我们都没打算以此赚钱，所以连介绍视频都没有做一个。或许这足够让我们有资格把自己的更多想法加进来了。
我们的Github开源项目直到今天仍然只有来自我们团队共用账号的一个star和view。我们也不清楚有没有除了我们之外的人在看这份手册。不过，弗兰肯斯坦会自己走向那个正常人统治的世界，我们也只做好我们愿意做的事就足矣。大家各自少吃一顿外卖，买token帮助我们开发的钱就出来了。所以我们没有前面宣称的那么惨，这个项目不需要帮助也能顺利运转，把你的钱花在更重要的事情上吧——比如在你妈妈生日的时候给她买点礼物什么的。
这个项目立项的时候，我们是只打算做完全游玩手册和少量配套卡牌的，直到某一天我们最擅长开发的人——也即唯一一个大一必修课里有信息技术导论，而且精通AI使用的人问了grok，这个项目是否可能通过热座式命令行游戏的形式呈现，然后它给了积极的回答。命运的齿轮就这么开始瞎转了。如果它当时回答很有难度，那这个项目就绝对不会有今天。
或许有些人会好奇这个游戏到底是一个带天赋的大逃杀，还是一个名场面生成器挂载了一个必要的底层运行系统。或许答案是介于两者之间，也或许已经从前者偏向后者。我们觉得，这得看你。如果没有神代天赋，这个游戏依然足以正常运转（把原初也去掉就费劲了），而在我们通过胜率天梯生成系统的观测中，七原初也并没有与五神代分层——比如新死者苏生是T0常青树。所以，答案应该是——你想怎么去玩，它就是什么样的游戏。昔涟说得好，世界温柔待我，我就长成温柔的模样。
又或者你会好奇这些像是疯子一样的神代天赋是怎么设计出来的。就当是在问我们的工作流程吧。很简单，我们是角色导向——某个上次团队聚餐出的钱最多的主创有资格给出TA厨的角色，然后提取这个角色身上的特征，并翻译进这个游戏，其他人会在此期间接触这个角色及其相关作品，并辅助TA完成翻译、少量取舍和严谨化，再交给其中对这个角色产生兴趣的人设计文案（其实没什么设计，基本都是从原著照搬来的，稍加改动），设计规则说明，写进游玩手册，然后丢给Devin之类的code Agent，再通过大量测试进行纠错和边界情况的检查和修复，最后更新AI使用这个天赋的逻辑，根据天梯生成系统进行数值平衡，上传远程仓库，发布更新。就这么简单，一个神代天赋从立项完成开始设计到最终上传不会超过五天。然后，下一次疯狂星期四的时候，会有新的设计被提出来，就这么循环下去。
所以，我们其实没有所谓的主美（我们连美术资源都没有），甚至没有专门的文案组、编程组和运营组之类的分工，每个人为了自己爱的角色连轴转，其他人帮助这个角色在游戏中以天赋的形式活过来。就这么简单。这次我们要更新的神代天赋也就这么简单——有个主创买了一套一日一星野系列漫画，然后就变成了大叔厨。说不定再过一阵我们还会做砂狼白子？空崎日奈？圣园未花？又或者人桌不分离的主教？神秘狐狸女若藻？传奇人机验证失败者爱丽丝？又或者提前帮牢梦打个复活赛？不知道，也有可能短时间内不会再有第二个来自BA的角色。在每个周四之前，没人知道下一个神代天赋会是什么，我们自己也不知道。
补充说明：为什么我们将列车大战和色彩反转两个被社区认为是黑历史和剧情崩坏的片段加入了神代天赋7的转译基础
如前面所见，团队里其实没人之前玩BA。那个大叔厨自己在高强度看剧情切片看二创的时候，其他人也在通过总结视频和网页百科之类的手段了解剧情梗概。所以这个问题的第一层答案就是——我们都不知道。后来考证，V1.3的版本剧情风波于24年影响日服，25年再次在国服掀起波澜。但它的风浪经过半年多的沉淀，还是在消退的。我们也选择无视了贴吧的那一大堆血腥图或者鬼图——主创团队玩米家游戏比较多，我们都亲身经历过崩三兔女郎事件、原神的开服抄袭塞尔达节奏和4.8勇者大人散兵风波、星穹铁道3.0版本阿格莱雅审判主角团风波、3.7版本昔涟两千元累充弓皮风波。对于一帮子堪称此世流溢之恨的人，如果一个角色正好能被用来发泄怨气，那会是什么惨状我们是有数的——甚至不需要去看社区。更何况有战力党小鬼在那玩星野和日奈踩一捧一这种败坏风气的行为。所以我们认为，这次剧情肯定存在问题，但如此大的风波不可能句句属实。
第二层原因是，我们最后分析认为，这次剧情的问题主要集中在那段非常抽象的商战上，而小鸟游星野的暴走和反转化本身没有什么设计问题。当然这句话可能会让创作团队的github注册邮箱被冲爆—冲吧，至少多一个人能看到我们。星野是二周目阿拜多斯最痛苦的人之一。她的早期剧情是非常经典的一失足成千古恨——和梦吵了一架，撂下来几句气话，然后前辈就惨死在沙漠之中。星野从头到尾都是务实派，她不喜欢梦的理想主义气息、也总看不惯她次次被骗。但作为还没有对策委员会的时代，两个阿拜多斯的守夜人，她们对彼此的依赖和影响是相当重的。栀子梦惨死之后，星野的转变更像是在后辈面前扮演一个像梦一样温柔可靠的前辈，所以她留了长发，放弃了自己像刀锋一样尖锐的攻击战术，变得看似慵懒而可爱，成为了剧情中sensei熟悉的样子和广大玩家熟悉的样子
但这终究只是个皮套。是星野用来扮演梦的皮套。或许这个皮套戴的越久就与她的性格愈发融合，但她的底色没有变——梦屡屡被骗的经历让她依然保持极度务实，不依赖任何人。这在一群没成年的学生中是并不多见的、接近于外热内冷的体现。她在阿拜多斯的第一年和后面两年是割裂的。她在后辈中还有一个特点是“过去极度神秘”，她不愿任何人接触那段历史，希望自己一个人挑起大梁，自己解决那一段过去所遗留下来的一切问题，这是她认为唯一可靠的解决方式。而她认为应该由对策委员会她同样没有看起来那样信任sensei，而sensei对她的过去也接近一无所知，两人无法在这件事上建立有效沟通，因此在V1.3中星野最终选择单走是符合她的人设的——和V1.2中星野单走去找黑服被签了卖身契一样。
很多人都觉得V1.2结束后星野不会单走了，会更加依赖和信任sensei。我们的结论是：信任有，依赖没有。最简单的证据就是：sensei还是不知道星野的过去；同样地，星野从来不向老师诉苦——简称没有敞开心扉。甚至V1.3结束时星野都愿意和sensei睡一起了也没有过。于是所有的苦难她都在一个人承受，不能向后辈解释就得不到她们的理解，为了列车炮的事情想保护她们，还要和她们交战，无数次冲开阻拦（这个有统计表做证，她就是鸡窝托斯超人）。何况还有地下老登可能在强化她的负面情绪，最终日奈的一句不理解让她彻底炸了，陷入自我怀疑进而反转。这一切的逻辑是很通顺的（但是写到这里难免有点心疼）。
BA的剧情有一个受到诟病的问题，就是很多真的犯了错的学生都没有得到惩罚，而是把责任自然地推到某个大人身上。最经典的例子是未花。但在这里，我们认为，地下老登并没有承担过多本不属于他的责任，做出这一连串的决定可能不符合上帝视角的逻辑，但很星野。V1.3的剧情反而在让她成长，补全第一年和后两年之间的裂隙，某一天真的愿意敞开心扉了也未可知。
因此，我们最终采纳了这些剧情作为在这个游戏中塑造她的基础。二游剧情可能是这样——心流混乱、编排不清、影响理解，甚至一度会让人以为OOC——它有很多问题，呈现的方式不够好。但没有这些剧情，星野就不是我们认识的星野了。
