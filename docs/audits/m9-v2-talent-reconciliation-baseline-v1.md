## 一、这次维护实际要解决什么

本轮不能把任务简化为“用更新的 M9 文档覆盖旧 V2”。任何主题都必须同时保留四列：

| 列 | 回答的问题 | 首要证据 |
|---|---|---|
| V2 玩家规则 | `v2exp` 玩家现在应当怎样理解规则？ | `docs/handbook/` 中审定后的主题模块 |
| V2 当前实现 | 程序现在实际怎样结算？ | 代码、测试、运行时验证 |
| M9 候选设计 | 下一代设计已经接受了什么方向？ | `docs/m9/current/` |
| 迁移决定 | 哪些保留、替换、分叉或暂缓？ | `docs/contradictions.md` 与逐项裁决记录 |

`docs/talents.md` 是混合参考，不能充当其中任意一整列。修改日期、文件名和“以代码为准”
也不能代替逐主题裁决。

## 二、已确认的系统级断层

### 2.1 V2 与 M9 是两个不同的行动合同

V2 候选手册、`engine/experiments.py`、`engine/round_manager.py` 和
`tests/test_k_initiative.py` 共同描述当前 `v2exp`：启用 `k_initiative`，按先攻排序后只让
前 `K = N - 1` 人取得行动权。

M9 v0.5 则冻结了另一份候选合同：全员一个标准行动槽、先攻只排序、SP 只决定天赋就绪。
这不是数值微调，而是会影响控制、额外行动、世界时钟、AI 估值和所有天赋时机的结构分叉。

### 2.2 “完整额外行动已拍板”不等于“迁移已经完成”

M9 已把完整额外行动限制为正面白名单，首批只有 T4「或跃在渊」和 T5 FC。当前实现仍有
多条独立入口，包括：

- T2 犯罪与警觉；
- T4「或跃在渊」，且当前一次写入两个额外行动；
- T5 FC 的通用 `pending_extra_turns`；
- G4 主动燃尽；
- G2 聚光合影；
- G7 临战-Archer 起床；
- 其他历史具名字段与通用追加回合通道。

因此，M9 的白名单原则已经决定，但每个旧入口要改为关注、追演、先攻、普通被动收益还是
删除，仍需逐项迁移决定。

### 2.3 SP 删除频率资源会穿透玩法之外的系统

M9 提议让 SP 接管纯次数、充能和冷却；当前代码与周边系统仍直接读取：

- `uses_remaining`；
- T4 `charges`；
- G1 `supernova_charges`；
- G6 `cutaway_charges`；
- G7 光环与修复冷却；
- AI 的天赋可用性和威胁估值；
- prompts、状态展示和测试断言。

这些字段不能按名称批量删除。必须先判定它是纯频率旋钮、战术资源、自动故事进度，还是
局部演出预算，再决定由 SP 取代或保留。

### 2.4 公演待遇仍缺少可实现合同

M9 v0.5/v0.2 已定义即演、公演与副舞台的边界，但公演增量依赖的 PP、魂援、投注、喝彩和
完结条仍主要来自部分失效的统一货币草案。以下内容尚未形成当前候选：

- 谁发起魂援、谁报价、何时锁定报价；
- PP 的生成、衰减、结算与评分关系；
- 普通公演约 `0.5 SAE` 增量如何落到十四天赋；
- G5“下一次公演”诗篇与当前即时改写资源的迁移；
- 死者、表演者和支援者的收益与责任归属。

在这份合同完成前，可以验证行动槽与 SP 状态机，但不能宣称完整 M9 演出系统已经可实现。

### 2.5 全员行动会放大控制，控制菜单尚未冻结

取消 K 后，眩晕、石化、睡眠等状态会从“可能扣掉一个本来也拿不到的回合”变成稳定影响
一个真实行动槽。M9 当前只冻结了“不要再用隐形行动值乘除”，尚未定义每种控制状态是：

- 替换根行动；
- 限制行动菜单；
- 允许付出代价解除；
- 仍然完整跳过行动。

这一层必须先于十四天赋数值风洞，否则 T3、G2、G3、G7 等控制效果没有稳定估值基准。

## 三、冲突分类与处理权限

| 类型 | 定义 | 是否可以直接修订 |
|---|---|---:|
| A：事实漂移 | 同一 profile 下，文档数字、字段名或说明与代码/`balance.json` 不一致 | 可在证据充分时修正文档；不得顺便改玩法 |
| B：V2 规范未决 | V2 玩家规则、混合参考与实现分别给出不同机制 | 先登记并由用户裁决哪一个应成为 V2 规范 |
| C：M9 迁移决定 | M9 已提出替代方向，但旧效果如何转换尚未定义 | 需要小型 RFC 或逐项决定 |
| D：实现偏差 | 规范或设计决定已经明确，代码尚未遵循 | 决定测试合同后才能修改实现 |
| E：profile 分叉 | Legacy、V2、M9 本来就应不同 | 分别记录，不做跨 profile 覆盖 |

每一项必须明确属于哪一类。不得以“当前代码如此”为理由把 B/C 自动判成 A。

## 四、正式裁决的五道门

### Gate 1：建立 V2 事实底稿

按主题核对玩家模块、`balance.json`、实现、测试、prompts、AI 可见状态。输出的是“当前证据
分别说了什么”，不是立即选一个赢家。

### Gate 2：写 M9 差异单

每个主题只记录 M9 相对已审计 V2 的变化：保留的角色特征、删除的频率资源、新的演出形态、
额外行动归属、公演增量和自动转折。

### Gate 3：完成设计裁决

对 B/C 类问题逐项拍板。每次决定必须回答：

> 这个角色的哪个特征，通过迁移后的什么机制体现？

未回答的问题保持 `decision-needed`，不得进入实现。

### Gate 4：建立独立原型合同

M9 不应静默改写 `v2exp`。完成行动、控制与 SP 模型后，优先建立独立实验 profile（暂称
`m9exp`，名称在实现任务中确认），让 V2 继续作为对照基线。

### Gate 5：实现、验证、转正

实现完成后再更新玩家规范。至少验证双人残局、六人局、控制、完整额外行动、同轮多次即演、
公演等待、副舞台和 500 局运行时烟雾；最后才把相关模块从 `candidate` 晋升。

## 五、十四天赋首轮分诊

优先级含义：P0 会阻塞行动底层；P1 可在行动合同后独立裁决；P2 依赖公演、副舞台或支援合同。

| 天赋 | 当前 V2 / 实现主要风险 | M9 迁移核心 | 首个待决问题 | 优先级 |
|---|---|---|---|---:|
| T1 | 手册、`talents.md`、代码的次数与伤害/穿甲表述需统一 | 删除次数，由 SP 控制主动斩击 | V2 核心斩击的准确边界是什么 | P1 |
| T2 | 多个被动触发会直接生成额外行动 | 保留犯罪与潜行身份，旧额外行动改为关注或追演 | T2 的“演出根入口”究竟是哪一个效果 | P0 |
| T3 | 次数、AOE、穿甲、石化在 V2 量纲下需逐项核对 | 删除次数，保留同地点大招与石化 | 全员行动下石化如何占用行动槽 | P1 |
| T4 | 4/5/6/9 轮口径并存；当前「或跃在渊」给两个额外行动 | 删除充能；保留随机命运；白名单授予一个完整额外行动 | V2 当前六种结果与 M9 的精确定义如何对齐 | P0 |
| T5 | Legacy 连续行动版与 V2 谱面版混写 | 保留谱面；FC 授予一个完整额外行动 | 奖励关、FC 与 SP 即演的时序 | P0 |
| T6 | 当前基本为全被动规则包 | 把远程举报作为主动演出入口，其余被动常驻 | 举报是天赋演出还是普通警务行动 | P1 |
| T7 | 学习、挂载、一次性复活和往世层交互未收口 | 主动布置伏笔，死亡时自动兑现，之后落幕 | 学习步骤在单行动槽下是否仍保留 | P1 |
| G1 | 炽愿是战术资源，但超新星次数是频率资源；仍有 hp20 裸值漂移 | 保留炽愿和失熵，删除独立过载次数 | 失熵/击杀怎样让超新星进入 SP 就绪 | P1 |
| G2 | 舞台、歌曲、Regard、物料与未接线草案并存 | 仅公演开放完整副舞台 | 序曲准备、开幕条件与外部时间是否继续推进 | P2 |
| G3 | 两次使用、结界内部行动与压制悬崖待审 | 仅公演开放结界，局部行动与外部槽隔离 | 幻想乡内部轮次和外部世界的时间合同 | P2 |
| G4 | 当前主动燃尽会授予额外行动，与 M9 明确冲突 | 濒死自动转折；强化后可主动；转折后 SP 置 2 | 删除主动额外行动后的主动燃尽价值如何补足 | P0 |
| G5 | 追忆、锚定、献诗、duet 与大量即时改写目标资源并存 | 保留追忆/锚定；诗篇改为下一次公演适配器 | 方式二的 V2 真值和公演适配要分别重写 | P2 |
| G6 | 依赖 K 轮空积累笑点/充能，并借用他人行动 | 删除轮空充能，改为重演公开动作模板 | 候选模板、费用、犯罪与责任的精确定义 | P0 |
| G7 | 起床额外行动、光环冷却、战术 Cost、Terror 同时存在 | SP 只管演出入口，Cost 保持局部预算，被动转折常驻 | 哪些冷却是战术状态，哪些只是发动频率 | P0 |

## 六、建议的内容维护批次

### B0：行动语义差异审计

只对照 K、全员行动、先攻、标准行动、追演、完整额外行动和控制，不改实现。列出所有当前
额外行动来源和控制消费路径，形成底层迁移表。

**状态（2026-08-05）**：事实审计已完成，见
[`m9-v2-action-semantics-b0-v1.md`](m9-v2-action-semantics-b0-v1.md)。B0 已确认现有队列缺少
追加回合来源/递归元数据，且 `acted_this_round` 混合了行动位、控制替代与自主行动语义；
控制菜单和部分旧追加回合的迁移仍保持待决。

### B1：最先受底层影响的五个天赋

按 T4 → T5 → G4 → T2 → G6/G7 的依赖顺序处理。目标是先关闭完整额外行动和 K 轮空的
旧入口，不在这一批处理 PP 或副舞台。

> 状态：已完成。事实证据与 B1-D01 至 B1-D06 的裁决记录见
> [`m9-v2-talent-action-migration-b1-v1.md`](m9-v2-talent-action-migration-b1-v1.md)；批准后的目标语义见
> [M9 天赋行动迁移合同 RFC v0.1](../m9/superseded/m9_talent_action_contract_rfc_v0.1.md)。

### B2：普通主动、被动与自动转折

处理 T1、T3、T6、T7、G1，并补齐 G4。确定哪些效果读取 SP，哪些常驻，哪些只在事件发生
时自动兑现。

> 状态：进行中。首轮事实、迁移候选与 B2-D01 至 B2-D08 见
> [`m9-v2-talent-trigger-migration-b2-v1.md`](m9-v2-talent-trigger-migration-b2-v1.md)。

### B3：副舞台与公演接口

处理 G2、G3、G5。先定义外部/内部时间、报名合法性和诗篇适配，再讨论完整数值。

### B4：PP、魂援、投注与评分

从部分失效草案中抽取仍可用的意图，另写当前 RFC；不在旧统一货币稿上继续追加补丁。

### B5：实现与玩家手册同步

每个已拍板主题用小提交实现和测试；通过验证后，更新对应模块、生成手册和冲突台账。

## 七、逐项审计记录模板

后续每个主题统一使用以下字段：

| 字段 | 内容 |
|---|---|
| 主题 ID | 稳定的机制标识 |
| V2 玩家模块 | 玩家应读取的候选规范 |
| 数值信源 | `balance.json` 键或明确的非数值规则 |
| 当前实现 | 入口、字段和结算时序 |
| 测试证据 | 已覆盖与缺失的场景 |
| M9 候选变化 | 保留、替换、删除或新增 |
| 冲突分类 | A / B / C / D / E |
| 用户决定 | 已接受、待决定或不适用 |
| 目标 profile | `legacy` / `v2exp` / `m9-rfc` / 未来原型 |
| 转正条件 | 实现、测试、运行时与文档检查 |

## 八、第一阶段的停手线

在 B0/B1 完成前：

1. 不修改 `engine/round_manager.py`、`engine/action_turn.py` 或天赋实现；
2. 不把 M9 文本写进 V2 玩家模块；
3. 不删除旧次数、充能、冷却或额外行动字段；
4. 不根据旧纸面推演宣称 v0.5 的并发强度已经通过；
5. 不同时调整世界时钟、伤害和行动数，以免失去对照基线。

这份停手线不阻止修正文档身份、登记事实漂移或补充只读审计工具。
