## 一、B1 首轮结论

1. T4、T5 是 M9 仅有的首批完整额外行动来源，但当前分别使用专用的两个回合字段和通用
   `pending_extra_turns`，都没有来源、深度、每轮上限或权限位。
2. T5 普通 FC 并非当前文稿声称的“结算后立即行动”：音符在 T2 判定，谱面通常到 R4 才
   结算；R4 写入的追加字段要等 T5 下次行动结束后才被 R3 队列读取。
3. G4 主动燃尽当前用一个额外行动补偿启动成本；删除它以后，必须明确主动与自动转折的
   `SP=2` 写入时点，否则公共演出收尾可能立刻把 SP 清零。
4. T2 当前有三条完整额外行动通道：犯罪、警觉和未写入 V2 玩家模块的响应窗口。犯罪与
   发现事件本身已经符合普通关注定义，若再额外送 SP，会形成重复奖励。
5. G6 当前由 K 轮空或自愿放弃积累笑点，再借用其他玩家的权限、资源和责任；这与全员行动
   及 M9“用自身状态重演公开模板”同时冲突。
6. G7 临战-Archer 起床后得到完整回合。它应迁为起床槽内的受限衔接；光环、战术 Cost 和
   宏疲劳属于战斗资源或战术状态，不应被 SP 批量删除。

B1-D01 至 B1-D06 已全部批准，目标语义已转入独立合同。B1 至此完成设计收口，但仍不修改
行动引擎、天赋实现、V2 玩家模块或数值。

## 三、当前 R3 追加顺序

当前 `round_manager._phase_r3` 只维护玩家 ID 队列。每个根行动结束后按代码顺序检查：

```text
响应窗口
→ T4 六爻
→ T2 犯罪
→ G4 主动燃尽
→ G2 聚光灯 / 合影
→ G7 起床
→ T2 警觉
→ pending_extra_turns（T5 等）
```

多个来源都使用 `insert(i + 1, ...)`；越晚检查的来源反而会被插到越前面。这个顺序不是规则
设计，只是插入实现的副作用。M9 必须先结算反应步骤，再按 `ActionGrant` 处理唯一合法的
完整额外行动，不能继承这条隐形优先级。

## 五、T4：或跃在渊

### 5.1 已冻结

- T4 以 SP 取得即演 / 公演入口，删除 `charges`、`max_charges` 和轮次充能。
- 六种命运结果继续保留；亢龙有悔的旧眩晕来源迁为震荡。
- 或跃在渊只授予一个 `full_extra`，不再用两个回合解释“补偿 + 奖励”。
- 阴阳之诗只能指定五种非或跃在渊结果；若想取得或跃在渊，只能保留正常随机。

### 5.2 当前额外漂移

- V2 模块开头的六效果摘要仍写“获武器 / 获甲 / 全体蓄力”，与同文件详细表及代码的
  天雷 / 夺甲 / 金身 / 禁武不一致。
- 当前 G5 自由选择菜单仍允许直接选择额外行动，且部分提示仍使用旧效果名。
- 当前没有测试直接锁定 `hexagram_extra_turn=2` 的队列顺序。

### 5.3 B1 候选时序

1. 六爻效果在当前行动槽内结算，只创建待派发的 `ActionGrant`。
2. 父行动先完成系统、根行动和演出收尾。
3. 因父行动打开的合法反应步骤先结算。
4. 反应栈清空后，或跃在渊的完整额外行动立即成为下一个全局行动槽。
5. 该槽允许即演、禁止公演、不刷新关注/SP 上限；若被控制消费则直接损失。

## 六、T5：FC

### 6.1 当前真实时序

T5 在 `on_turn_end` 判定 Perfect / Good，但只有 R4 的 `on_round_end` 会在所有音符已有结果时
调用 `_resolve_chart`。因此普通 FC 的追加字段在 R4 才出现，而 R3 只会在 T5 结束一次行动后
读取该字段。结果通常是：

```text
R(n) T2：最后一个 Perfect 已完成
→ R(n) R4：结算 FC，pending_extra_turns += 1
→ R(n+1) T5 先执行自己的标准行动
→ 该行动结束后才插入 FC 额外行动
```

这不是“FC 后立即奖励”，也会让死亡、控制和下一轮状态意外夹在奖励之前。

### 6.2 B1 候选时序

- 每次 T2 写入音符结果后，若整张谱面已经全部判定，立刻结谱。
- 最后一个结果为 Perfect 且全谱全 Perfect 时，在该 T2 创建一个 `full_extra`。
- Good / Clear 也可在全谱判完的 T2 提前结算，但不创建额外行动。
- 只有仍有空白音符并因窗口过期形成 Miss 的谱面留到 R4 结算。
- G5 不能把音符改成 Perfect，也不能直接制造 FC；相关旧实现留给 B3 迁移。
- 若最后一个 Perfect 发生在本轮已经取得的完整额外行动中，每轮上限与深度规则阻止再次
  生成完整额外行动。

## 七、G4：燃尽与 SP

### 7.1 当前冲突

主动燃尽目前消耗 T0 所在行动回合，再授予一个完整额外回合。M9 已删除后半段，并用
“转折后 SP 置为 2，把下一次使用救世主核心的时点交还玩家”替代。

若主动燃尽作为一次演出先把 SP 置 2，再执行通用演出收尾，SP 会立刻归零；这会让主动燃尽
同时失去额外行动和就绪交还。另一方面，只让自动燃尽置 2，会使 G5 解锁的主动入口明显弱于
已经批准的转折身份。

代码另有独立数值漂移：`balance.json` 的火种上限为 20，当前 `Savior.MAX_DIVINITY` 仍硬编码
为 12。它进入 B2/B5 数值迁移，不在 B1 顺手修改。

### 7.2 B1 候选时序

- 自动和主动燃尽都只执行形态转折，不授予行动槽。
- 当前行动 / 伤害事件完成全部公共收尾后，再把 G4 的 SP **设置**为 2；不是 `+2`。
- 主动燃尽已经占用的行动槽不会因此恢复，玩家只能在下一个合法 T0 使用这份就绪。
- 若自动燃尽发生在 G4 本轮尚未行动之前，轮到 G4 时即可使用；若已经行动，则保留到后续轮次。
- 置 2 不刷新本轮关注上限，也不自动报名公演。

救世主形态内“下一次演出的核心效果是什么”属于 B2，不用额外行动临时顶替。

## 八、T2：犯罪、警觉与响应

### 8.1 当前三条通道

1. 首次新犯罪类型通过 `crime_extra_turn` 插入自身完整回合。
2. 首次找到他人或首次被找到共用一次 `vigilance_uses`，通过
   `vigilance_extra_turn` 插入完整回合。
3. 隐藏响应窗口可在任意其他玩家行动后询问 T2；当前代码不按行动类别、距离或目标关系
   过滤，确认后直接插入完整回合。V2 玩家模块没有登记这一子效果。

### 8.2 B1 候选迁移

- 删除犯罪和警觉的专属追加字段，也不额外直接赠送 SP。
- 合法犯罪、高影响 find，以及成为 find 焦点，按普通关注规则登记；仍受每人每轮最多
  `+1 SP` 的共同上限。这样不会对同一个高影响事件重复奖励。
- 伤人未杀免罪、攻击回盾和零击杀隐身继续作为常驻身份。
- 响应窗口保留为全局一次的“追猎反应”：另一名玩家的公开根行动完成后，若 T2 能以
  自身状态对该行动者合法执行 `find` 或 `lock`，可立即执行其中一个。
- 追猎反应不移动、不攻击、不进入 T0、不创建行动槽；费用、权限、犯罪和关注均归 T2。
- 反应结算完成后，才派发父行动产生的完整额外行动。

T2 的即演 / 公演核心仍沿用天赋 RFC：即演攻击一个已发现或锁定目标，公演才可获得追猎移动。

## 九、G6：公开模板重演

### 9.1 需要退役的旧结构

- K 轮空和自愿放弃产生笑点；
- `laugh_points`、`cutaway_charges`、强制 D4/D6 和诗篇降低放弃阈值；
- 枚举其他玩家当前可做动作，并借用其身份、钱包、警队权限和犯罪责任。

全员行动后，第一条只剩“主动放弃六次换一次发动”的负反馈；后三条又让责任归属与 B0 的
根行动记账无法闭合。

### 9.2 B1 候选模板合同

1. 每个 R4 从本轮已经完成公共收尾的公开根行动中生成模板，按行动大类去重。
2. 第一版只记录 `move`、`interact`、`find`、`lock`、`attack` 五类；起床、放弃、控制替代、
   天赋演出、警察指令、副舞台和未登记 special 不进入模板池。
3. G6 即演时可从上一轮模板中选择一类，再以 G6 自己的当前位置、装备、资源、权限和合法
   目标重新选择参数。
4. 模板只许可动作大类，不复制原行动者、目标、武器、数值、额外行动或战果。
5. 费用、犯罪、威信、关注、物品与击杀全部归 G6；它就是 G6 的本槽根行动。
6. 某类当前无合法参数时不可选；所有模板都不合法时，演出在合法性检查前取消，SP 保留。
7. 欢愉之诗把候选窗口从上一轮扩至最近两轮，不授予充能或额外模板次数。

警察指令与可复制 special 以后若需要开放，必须逐项加入正面 `copyable` 白名单。

## 十、G7：起床受限衔接与资源分类

### 10.1 B1 候选受限菜单

临战-Archer 每次合法起床后，可在同一个起床槽内选择执行至多一个：

- `move`；
- 非敌对 `interact`；
- `find`；
- `lock`；
- 或结束行动槽。

这不是新的 `ActionGrant`，不重新经过 T0，不能攻击、使用警察指令、special、即演或公演。
若执行了衔接动作，则该动作是本槽唯一根行动并执行相应根行动收尾；整个槽仍只执行一次
系统收尾，建议登记 `resolution_kind=wake_followup`。单纯起床并结束仍是
`root_action_performed=false`。

### 10.2 保留的专属资源

| 结构 | 分类 | B1 处理 |
|---|---|---|
| 光环及串行恢复 | 可被伤害消耗的再生战斗资源 | 保留，不交给 SP |
| 战术 Cost | 单次宏内的局部编排预算 | 保留；3/4 Cost 数值在后续原型处理 |
| 宏疲劳 | 下一轮 Cost 修正的战术状态 | 保留 |
| 融合装备、弹药、色彩、Terror | 装备、战术与故事进度 | 保留 |
| 铁之荷鲁斯 0 修复量冷却框架 | 已失去实际收益的实现残留 | B5 清理候选，不视为天赋资源 |

## 十二、测试证据与缺口

本批次运行：

```text
python -m pytest tests/test_k_initiative.py tests/test_t5_combo_hp20.py \
  tests/test_m7_talents.py tests/test_g7_hoshino_hp20.py \
  tests/test_g5_phase2.py tests/test_m9_talent_spotlight_simulation.py -q

```

现有测试确认当前 T5 FC 写入通用追加字段、G6 旧充能、G4 数值与 G7 战斗资源，但没有覆盖：

- T4/G4/T2/G7 专用追加字段的跨来源顺序；
- 普通 T5 FC 从 R4 延迟到下一轮行动后的真实队列结果；
- 反应步骤先于完整额外行动；
- G6 公开模板的记录、去重、重新验证与责任归属；
- G7 起床衔接只执行一次公共收尾；
- 每人每轮一个完整额外行动和深度阻断。

这些已经成为目标合同要求的原型测试，不能按当前偶然字段补成永久规范。
