## 一、B0 结论

1. 当前 `v2exp` 的 K 制不是“先攻展示差异”，而是 R1 直接裁掉默认一名行动者；M9
   的全员行动需要新的行动授予合同，不能只把 K 改成 N。
2. 当前 R3 队列只保存玩家 ID。所有从外部插入的追加回合都会重新执行完整
   `T0 → T1 → T2`，但队列无法说明来源、根行动、递归深度或是否允许公演。
3. 当前控制效果存在四种不同消费方式：清除后继续、恢复并结束、付代价后继续、直接替换
   整个行动。多个提前返回还会跳过 T2。
4. `acted_this_round` 同时近似表示“进入过队列”“完成过某种结算”和“做过自主行动”，
   已不足以支撑 M9 的标准行动、控制替代和完整额外行动。
5. M9 已冻结全员标准行动槽、完整额外行动白名单、控制裁决器、伤害两阶段和统一收尾。
   眩晕退出 M9 通用状态，旧来源迁为震荡；压制作为未来正面白名单的最高级控制预留。

因此 B0 已完成，可以按 T4、T5、G4、T2、G6、G7 的依赖顺序进入 B1。
具体目标语义集中在结算合同 RFC v0.1；本批次没有修改玩家手册或代码。

## 三、当前 V2 行动生命周期

### 3.1 R1 到 R3

| 时点 | 当前行为 | B0 判定 |
|---|---|---|
| R1 入选 | 所有存活玩家参加先攻；睡眠和控制状态不在此处排除 | 控制目前转换已经取得的行动，不改变入队资格 |
| R1 排序 | 掷 D6 加先攻修正；同点补掷，再比较修正和玩家原始顺序 | 可作为 M9“先攻只排序”的基础 |
| R1 配额 | 默认 `K = max(1, 存活参赛者数 - k_sitout_count)`，当前默认轮空一人 | 与 M9 全员行动直接冲突 |
| G2 舞台 | active/duet 时配额改为全员并包含 Chorus；R3 再把 G2 置顶 | 是现有全员队列的局部先例，不等于通用 M9 合同 |
| R2 | K profile 下直接跳过旧同地点先后手重排 | M9 可继续只保留一次全局先攻排序 |
| R3 队列 | 从 `round_winners` 复制玩家 ID 列表，运行时在当前位置后插入更多 ID | 缺少行动类型和来源元数据 |
| 单个队列项 | 普通玩家调用完整 `execute_action_turn()`；Chorus 只执行自身 T1 | 当前追加回合默认也是完整行动，但没有明文资格检查 |

### 3.2 当前普通玩家回合

```text
进入队列
  ├─ 未起床：起床后立即结束
  └─ 已起床：T0
       ├─ 控制或天赋提前返回：立即结束
       └─ 正常：T1 根行动 → T2 → 返回 action_type
R3 根据 action_type 更新 acted_this_round，再扫描所有追加回合字段
```

这说明“进入过行动位”不保证经过 T2，也不保证玩家获得过 T1 的自主选择。

## 四、控制如何消费当前行动位

| 状态/分支 | 当前 V2 实现 | 是否进入 T1 | 是否进入 T2 | 当前 `acted_this_round` 结果 | M9 已定 / 未定 |
|---|---|---:|---:|---|---|
| 睡眠 | 队列项只执行起床，然后返回 `wake` | 否 | 否 | 是 | 已定方向：当前行动只能起床 |
| 普通眩晕 | T0 清除眩晕，之后继续正常回合 | 是 | 是 | 按根行动记账 | RFC 写“受限菜单”，与实现和 V2 手册均不一致，待定 |
| 黄昏延长眩晕 | 保持眩晕，返回 `stun_extended` | 否 | 否 | 是 | 是否仍完整剥夺行动待定 |
| 震荡 | 通常清除震荡，返回 `shock_recover` | 否 | 否 | 否 | RFC 未单列震荡菜单，待定 |
| 黄昏延长震荡 | 保持震荡，同样返回 `shock_recover` | 否 | 否 | 否 | 与普通恢复共用返回值，事实不可区分 |
| 石化：解除 | 解除并承受 `hp20.petrify_release_damage`；存活则继续 | 是 | 是 | 按根行动记账 | 已有“付代价解除”原型；是否保留待定 |
| 石化：保持 | 保持石化，返回 `petrify_skip` | 否 | 否 | 是 | RFC 要求明文禁止类别，具体菜单待定 |
| G7 自我怀疑 | `on_turn_start` 消耗回合并完成 Terror 转化 | 否 | 否 | 通常是 | 已定方向：下次行动替换为转化；需统一结算合同 |
| G3 结界施术者 | 自动解除眩晕、震荡、石化并继续 | 是 | 是 | 按根行动记账 | 属副舞台特殊规则，B3 再审 |
| G3 结界内目标 | 本地结界行动中若受控则直接跳过 | 不适用 | 不适用 | 不走全局 R3 记账 | 属局部子舞台，不应混入全局控制合同 |
| G2 舞台所有者 | 舞台内自动解除硬控后继续 | 是 | 是 | 按舞台行动记账 | 属副舞台特殊规则，B3 再审 |

### 4.1 当前文稿和实现的三方差异

- V2 手册把眩晕概述为“失去下个行动回合”，实现却通常在 T0 清除后继续完整行动；只有黄昏
  延长分支会真正跳过。
- M9 RFC 把眩晕描述为挣脱、防御等受限菜单，但菜单尚未定义，也没有实现证据。
- 震荡在当前实现中稳定占用一次队列项用于恢复，但 `acted_this_round` 又把它排除为未行动；
  睡眠和保持石化同样没有 T1，却会被记为已行动。

这不是单一文本错误，而是需要设计裁决和记账拆分的组合问题。

### 5.1 当前追加回合的结构风险

1. 队列项只有玩家 ID，无法区分标准行动和完整额外行动。
2. 具名 flag 通常在插入前清零，因此后续回合不能可靠判断自己的来源。
3. 任何追加回合结束后都会再次扫描全部追加字段，当前没有统一递归深度或每轮上限。
4. 当前没有统一入口禁止追加回合内再次取得公演、刷新关注或生成第二个追加回合。
5. T4 当前是两个追加回合，而 M9 白名单只接受一个；这属于明确的迁移差异，不是文案误差。

## 六、不是“全局完整额外行动”的相邻机制

| 机制 | 当前真实语义 | M9 分类建议 |
|---|---|---|
| G3 幻想乡内部行动 | 在 T0 内同步运行施术者额外动作与局部轮次，不进入全局 `action_queue` | 局部子舞台预算；B3 定义内外时间 |
| G6 插入式笑话 | 替换 G6 本次 T1 可选动作模板，不新增全局队列项 | 根行动替换/动作模板重演，不授予完整额外行动 |
| G2 舞台全员行动 | R1 配额模式覆盖，舞台参与者本轮全员入队 | 舞台行动资格规则，不是额外行动奖励 |
| 追演 | 当前实现没有统一底层对象；M9 定义为根行动内最多一次附加步骤 | 未来作为根行动子步骤，不开新 T0/T2 |

这个区分用于避免 B1 把所有“多做了一件事”都错误迁成完整额外行动。

## 七、M9 目标行动语法

以下是已接受 RFC 的重新表述，不新增规则：

| 术语 | 目标边界 |
|---|---|
| 标准行动 | 每名正常存活玩家每个全局轮次一个；先攻只排序 |
| 根行动 | 标准行动或完整额外行动在 T1 选择的主要行动 |
| 追演 | 根行动内部、明文限定类别的一段附加步骤；不开新 T0；同一根行动最多一次；不可递归 |
| 完整额外行动 | 正面白名单授予的新行动槽；完整经过 T0/T1/T2；立即插入；每玩家每轮最多一个；不可递归；不得公演 |
| 控制替代 | 玩家仍取得本轮行动位，但该行动的菜单、代价或用途被状态明文改变 |
| 局部子舞台行动 | 只在 G2/G3 等封闭规则内存在；默认不与全局行动槽相互带入或带出 |

## 八、原型前需要的数据合同

本节是实现需求草图，不是要求本批次改 `round_manager.py`。

未来 R3 不能继续只传玩家 ID。最小行动授予记录至少需要表达：

| 字段 | 用途 |
|---|---|
| `actor_id` | 谁取得行动 |
| `kind` | `standard`、`full_extra` 或局部子舞台类型 |
| `source_id` | 由哪条明文规则授予 |
| `global_round` | 用于每轮最多一个完整额外行动 |
| `root_id` / `depth` | 防止追加回合递归 |
| `allow_instant` | 完整额外行动可否在 T0 即演 |
| `allow_public` | 完整额外行动固定为否 |
| `refresh_limits` | 是否允许刷新关注/SP 等每轮限制 |

同时应把现有记账至少拆成四个事实：

- `slot_assigned`：本轮是否获得行动位；
- `slot_resolved`：该行动位是否完成结算；
- `root_action_performed`：是否实际执行自主根行动；
- `resolution_kind`：普通、起床、控制替代、自愿放弃、完整额外行动等。

字段名可以在原型设计时调整，但这些语义不能继续由单个 `acted_this_round` 推断。

### 9.1 已批准的控制梯度

控制按状态身份而不是统一模板处理：

1. **睡眠**：行动只用于起床，属于结构状态；
2. **震荡**：进入移动、非敌对交互、帮助/唤醒或自愿放弃的受限菜单；
3. **石化**：付代价解除并正常行动，或保持石化并执行极小菜单 / 跳过；
4. **压制**：作为最高级控制，强制消费下一次实际获得的行动槽；
5. **自我怀疑**：固定把下一行动替换成 Terror 转化，因为它是剧情转折而非通用控制。

普通控制位的优先级为 `压制 > 石化 > 震荡`；睡眠和自我怀疑独立保留。
完整动作类别、免疫边界和消费规则以结算合同 RFC v0.1 为准。

## 十一、B0 完成与 B1 入口

B0 已完成“现状事实、目标状态与原型前置合同”的拆分。下一批按顺序处理：

1. T4：两个追加回合迁为一个完整额外行动；
2. T5：FC 的通用追加字段迁为白名单授予；
3. G4：删除主动完整额外行动后的主动价值；
4. T2：犯罪和警觉从完整回合迁为关注/演出入口；
5. G6/G7：K 轮空依赖、动作模板重演与起床追加回合。

B1 先冻结逐天赋迁移与时序，不直接改行动引擎。需要实现时另立原型批次，并以结算合同
中的控制、伤害、公共收尾和 `ActionGrant` 作为合同测试依据。
