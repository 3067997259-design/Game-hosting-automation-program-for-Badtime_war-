## 一、合同目标

1. 每个正常存活者取得行动槽后，状态只改变该槽如何结算，不再依靠偶然的提前返回。
2. 常规控制保留代价，但不再让多个名称重复表达同一种“整回合坐牢”。
3. 攻击方先得到最终攻击伤害，承受方再得到最终造成伤害；所有乘区和下限都有唯一位置。
4. 完整额外行动仍是最高级正面奖励，但必须由明文来源授予并阻断递归。
5. 天赋只保留真正改变决策的专属状态；通用状态使用统一身份、叠加和移除规则。
6. 伤害身份统一收敛：`DIRECT_DAMAGE` 是唯一登记的直接伤害身份，各天赋 RFC 不得自造
   “真伤”语义；`absolute_death` 标签独立决定是否跳过普通死亡替代、免死与复活。
7. “有效伤害”是单一公共口径，任何条件类效果（石化解除、追忆记录、护盾破盾判定等）
   都引用同一定义，不再由各天赋各写各的判定。

## 二、状态分类与命名

| 类别 | 状态 | M9 身份 |
|---|---|---|
| 普通行动控制 | 震荡 `SHOCKED` | 唯一通用受限行动控制 |
| 高级行动控制 | 压制 `ACTION_SUPPRESSED` | 不可被常规反制的下一行动槽跳过 |
| 选择型控制 | 石化 `PETRIFIED` | 付出代价解除，或保持并放弃/缩减本槽 |
| 结构状态 | 睡眠、自我怀疑 / Terror、**流放 `EXILED`** | 改写行动阶段的剧情或结构状态，不属于普通 debuff |
| 伤害 debuff | 易伤 `VULNERABLE X` | 承受方的固定值增伤 |
| 伤害 debuff | 虚弱 `WEAKENED X` | 攻击方的固定值减伤 |
| 防御状态 | 掩体 `COVERED` | 地点绑定、独立耐久的临时防御物 |
| NPC 控制 | 沉沦 `SUBMERGED` | 来源绑定的非玩家单位停机状态 |
| 持续伤害 | 灼烧 `BURNING` | 保留现有可叠层 DOT 身份 |

以下名称不再占用新的通用状态：

- **眩晕**退出 M9 独立名录；旧来源在逐技能迁移时改为震荡，不自动升级为压制。
- G3 `v2exp` 的“天赋压制”只保留为旧机制称呼；M9 投影固有结界已删除全面天赋关闭，
  跨结界目标或递归公演因作用域不合法而失败，不另登记“天赋封锁/封印”状态。
- `INVISIBLE_SUPPRESSED` 的玩家可见名称应改为“隐身失效”，它不是行动压制。
- 舞台声部、聚光、往世层等仍是天赋或副舞台局部状态，不登记为通用 debuff。

## 三、普通状态合同

### 3.1 震荡

震荡是 M9 唯一通用的受限行动控制。其下一次实际获得的行动槽只能选择：

- 移动；
- 非敌对交互；
- 帮助 / 唤醒；
- 自愿放弃。

该槽禁止攻击、寻找 / 上锁、警察指令、主动天赋、即演与公演。结算后在公共收尾中移除
震荡。震荡不叠层、不排队，也不因同级重复施加而隐式延长。

陶瓷护甲只免疫**电流来源**施加的震荡；冲击来源或 T4 等非电流来源不因此免疫。

### 3.2 石化

石化保留选择权：

- 支付效果规定的代价后解除石化，并在同一行动槽正常行动；或
- 保持石化，执行来源允许的极小菜单；若来源没有明文菜单，则该行动槽跳过。

石化的解除代价由当前 profile 的数值信源或具体来源提供，本合同不复制数值。
被动解除类判定的“有效伤害”一律使用 §6.7 的统一口径（见 T3 v0.3“尘世之锁”）。

### 3.3 易伤与虚弱

- 易伤 `VULNERABLE X`：在承受方结算中增加固定值 `X`。
- 虚弱 `WEAKENED X`：在攻击方结算中减少固定值 `X`。
- 同名效果同时存在时取最高数值，不相加；持续时间和施加时点由来源明文给出。
- 两者都不是独立乘区，也不得自行生成新的百分比乘区。
- 普通虚弱不能把正的最终攻击伤害降到 `0`；只有明文“攻击归零”效果拥有该权限。

### 3.4 掩体

掩体是地点绑定的临时防御物，不占用护甲栏，没有普通 / 科技 / 魔法属性：

- 具有来源规定的独立耐久和持续时间；同一单位至多拥有一个掩体，较大的耐久替换较小者。
- 远程直接攻击必须先命中掩体；近战、同地点攻击、环境伤害和明文无视掩体的效果绕过。
- 掩体被击破的那次攻击不向本体溢出伤害。
- 单位主动或被强制离开地点时立即失去掩体。

### 3.5 沉沦

沉沦仅用于 NPC 或类似非玩家单位：

- 沉沦期间不能接受指令、移动或自动行动，也不能提供被动保护与警察保护。
- 它由来源维持；来源存在时，普通唤醒或普通净化不能移除。
- 来源结束时沉沦随之结束。

沉沦与压制不同：前者关闭 NPC 的行动和被动输出，后者只消费下一次激活机会。

### 3.6 流放 `EXILED`：结构状态（2026-08-09 v0.3）

流放是把单位移出普通行动层的**结构状态**，不属于普通 debuff，不占普通控制位：

- **脱离普通层**：被流放单位在来源持续时间内在普通行动层之外，不进入 R1 先攻、不获得
  标准行动槽、不进入公演队列，也不能成为任何普通行动、技能、控制或伤害的目标，不能
  交互、不被掩体保护，也不提供被动保护。
- **无槽、无目标、无交互**：流放期间单位的所有普通互动能力被关闭；只有来源明文允许的
  例外可以触达它（例如按来源显式更高的层级效果）。
- **返回顺序**：来源结束时，单位先返回**进入流放前原属的合法位置**；若该位置已不可
  站立，则使用**最近安全地点兜底**——与 G1 最后安全地点兜底同一套规则，平局按确定性
  顺序裁决（先攻降序，再按 actor ID，不做随机，见 G1 v0.3 §五）。
- **建立轮 R4 不 tick**：流放的持续时间遵循行动 v0.8 的“建立轮 R4 不 tick”规则——
  从效果建立之后第一个 R4 开始扣第一段，除非来源明文写明从建立当轮开始计时。
- 流放不自动清空 SP（与死亡不同）；但离场期间公演队列资格暂停，返回后按行动 v0.8
  §6.2 重新报名。

流放与死亡的区别：流放是临时的结构状态，来源结束即返回；死亡触发 SP 清零与队列移除
（§6.8），并进入死亡 / 复活流程。

## 四、行动控制裁决器

行动槽开始时按以下固定顺序裁决：

1. 死亡、离场或不在普通行动层（含流放）：不授予普通行动槽；
2. 压制：消费本槽并强制跳过；
3. 自我怀疑：执行 Terror 转化；
4. 睡眠：本槽只能唤醒；
5. 石化：选择解除并行动，或保持并放弃 / 缩减；
6. 震荡：进入受限菜单；
7. 无以上状态：正常行动。

普通行动控制共享一个控制位，优先级为：

```text
压制 > 石化 > 震荡
```

- 新的高优先级控制会替换并清除已有低优先级控制。
- 低优先级控制不能在高优先级控制仍存在时生效。
- 同级重复施加不叠层、不排队、不隐式延长。
- 睡眠、自我怀疑与流放属于结构状态，不占普通控制位，也不会被压制清除。

因此，“睡眠 + 压制”会先由压制消费一个行动槽，之后仍需另一个行动槽唤醒；
“自我怀疑 + 压制”同理，Terror 转化会保留到后续行动槽。

## 五、压制合同

压制是最高级行动控制，玩家可见名为“压制”，建议内部 ID 为
`ACTION_SUPPRESSED`：

- 它作用于目标**下一次实际获得**的行动槽，包括标准行动与完整额外行动。
- 它不打断已经开始的当前行动。
- 被压制行动没有 T0 / T1，不允许移动、交互、自愿放弃、即演或公演。
- 该槽仍执行系统公共收尾，并登记：
  `slot_resolved=true`、`root_action_performed=false`、
  `resolution_kind=suppressed`。
- 不触发自主行动、演出或自愿放弃对应的奖励与钩子；结算后立即移除压制。
- 压制为二值状态，不叠层、不刷新、不排队；结算前重复施加不能储存多个跳过回合。
- 普通净化、控制免疫、护盾、爱愿与普通屏障不能抵抗压制；旧有“免疫全部 debuff / 控制”
  不能自动覆盖它，必须由正面白名单明文写出。
- NPC 被压制时跳过下一次激活 / 指令机会，但仍保留被动效果。

首个技能白名单是 G2 v0.3 世末终曲：每次终曲至多使用登记次数，在区域内非 G2 actor 的
实际 `ActionGrant` 建立、根行动前公开消费，使该槽按本节 `ACTION_SUPPRESSED` 收尾。除此
之外仍不能把旧眩晕或普通控制批量升级为压制。

## 六、两阶段伤害合同

### 6.1 攻击方：最终攻击伤害

先计算最终攻击伤害 `A`：

```text
A = max(0, round_half_up(
    base_damage * skill_core_multiplier
    + attacker_flat_bonus
    - weakness
))
```

- `skill_core_multiplier` 是技能核心倍率位。一条攻击只取一个有效核心倍率，不把多个来源
  隐式连乘。
- 普通增益、世界时钟、喝彩、援助和 debuff 默认只进入固定值项。
- 百分比“攻击力系数”只能作为极少数明文特例，不能由普通虚弱或普通增益自行产生。
- 若没有“攻击归零”权限，正的基础攻击经虚弱后最低得到 `A=1`。

### 6.2 承受方：最终造成伤害

再由目标侧计算最终造成伤害 `H`：

```text
E  = round_half_up(attribute_defense * defense_coefficient)
H0 = A + vulnerability - flat_damage_reduction - E

if A > 0:
    H = max(H0, ceil(A * 25%))
else:
    H = 0
```

- 易伤在目标侧加入，不抬高 `25%` 下限的基准。
- 多个防御穿透或防御系数同时存在时，取最低有效 `defense_coefficient`，不彼此相乘。
- M9 常规属性关系使用防御力结算，不再让普通三角克制把整次有效攻击直接归零。
- 本合同不建立“最终伤害倍率”通用乘区；需要最终改写伤害的效果必须进入明文白名单。
- M9 所有从小数转整数的结算统一使用 **round half-up（对半分时向上取整）**；不得调用
  语言默认的银行家舍入。`ceil` 明文出现时仍按向上取整，不改写成 half-up。
- 唯一当前明文例外是 G2 终曲共享比例的 `floor` 抽取；该例外只作用于 §6.7a 的 S，不扩散
  到其他伤害或资源公式。

### 6.3 `25%` 下限与擦伤

`25%` 下限以**最终攻击伤害 `A`**为基准，而不是原始武器伤害，也不是加入易伤后的数值：

- 正常防御、减伤和属性防御不能把 `A>0` 的攻击压到 `ceil(A×25%)` 以下。
- “擦伤”就是恰好造成 `ceil(A×25%)`，不是另一个独立伤害类型。
- 虚弱在攻击方阶段降低 `A`，因此也会降低该攻击自己的下限；这使攻击力削减成为稀有而
  有辨识度的层，而不需要新增乘区。
- `DIRECT_DAMAGE` 直接令 `H=A`，不再需要 `25%` 下限（见 §6.6）。

### 6.4 攻击归零

`A=0` 是攻击方阶段的终极惩戒结果，只允许以下正面白名单：

- 攻击本身无效；
- 效果明文写有“本效果可以令最终攻击伤害降为 0”。

当 `A=0` 时：

- 不启用 `25%` 下限；
- 不消耗本体护甲或掩体耐久；
- 不视为造成伤害；
- 需要继续生效的非伤害负载必须由来源单独明文说明。

最终对本体造成 `H=0` 还可以来自承受方的绝对免疫、掩体 / 替身 / 合法重定向完全承接，
或攻击不在本体的有效结算层。此时若 `A>0`，承接者仍按自身规则承担攻击；例如掩体会
损失耐久，但 `25%` 下限不会强迫伤害溢出到本体。这不等于把攻击方的 `A` 改成 `0`。

实现时必须在通用最小伤害函数之前短路 `A=0`；不能让“最小伤害为 1”的旧函数把它恢复。

### 6.5 T1 在新合同中的位置

T1 的 M9 身份为：

```text
skill_core_multiplier = 2
defense_coefficient   = 0.5
```

即先把武器有效伤害乘 `2`，再加攻击方固定值；目标侧只计算一半属性防御。
旧的“无视最后内层吸收”只保留在 legacy 兼容语义中，不进入 M9 / V2 防御力合同；
`ignore_counter` 也不能继续充当已经退役的整次属性无效逻辑。

### 6.6 `DIRECT_DAMAGE`：直达伤害身份（2026-08-09 B5 W9 批准）

`DIRECT_DAMAGE` 是 M9 唯一登记的直接伤害身份，取代各天赋 RFC 自造的“真伤”语义：

```text
H = A
```

- 直接跳过目标侧的属性防御 `E`、护甲与普通 `flat_damage_reduction`；
- 因为 `H=A`，`25%` 下限在此**不适用且不必要**；实现不需要为它调用通用最小伤害函数，
  也不需要再套一遍 `ceil(A×25%)`；
- 攻击方阶段的结算照常：`A` 仍经过技能核心倍率、攻击方固定值、虚弱与攻击归零规则，
  只是不再进入目标侧防御流水线；
- **仍然可以被明文承接拦截**：替身、合法重定向、绝对免疫、掩体 / 保护承接等明文
  效果依旧按自身规则承接该伤害，`DIRECT_DAMAGE` 不等于“必中”或“必杀”；
- 伤害、关注（E1/E4/E5）与死亡流程照常登记；它不是自动的绝对死亡。

**绝对死亡是独立来源标签**：`DIRECT_DAMAGE` 本身不跳过 T7 保险复活或任何死亡豁免；
只有来源额外携带 `absolute_death` 标签时才跳过。首批登记来源：

| 来源 | 伤害身份 | 绝对死亡 |
|---|---|---|
| G0 十字炮火 | `DIRECT_DAMAGE` | 否（普通死亡流程） |
| G7 Terror 攻击 | `DIRECT_DAMAGE` | 是（Terror 挂载复活不生效，见 G7 v0.3） |
| G4 死星天裁 | `DIRECT_DAMAGE` | 是（B5 W3，附带绝对死亡标签并跳过 T7） |
| 终焉世界时钟 R4 伤害 | `DIRECT_DAMAGE` | 否（环境伤害，无击杀者，普通死亡流程） |

终焉世界时钟沿用基础游戏 `world_clock.apocalypse.end_of_round_true_damage` 数值键，但
在 M9 中统一登记为环境 `DIRECT_DAMAGE`，不携带 `absolute_death`，不生成击杀者。任何其他
效果要取得 `DIRECT_DAMAGE` 身份，必须在自身权威合同明文登记；禁止以“真伤”“无视护甲”
“攻击归零”等旧措辞自动推导该身份。

### 6.7 有效伤害：统一公共口径（2026-08-09 v0.3）

“有效伤害”是所有条件类效果共用的单一判定，不再由各天赋各写各的：

```text
一次伤害结算构成「有效伤害」，当且仅当满足以下任一条件：
① 最终造成伤害 H ≥ 1 进入本体 HP（哪怕 1 点）；
② 击破一个护甲或掩体对象（其耐久在本次结算中降到 0）。
```

**不计入有效伤害**：

- 只造成普通耐久损耗、未击破护甲/掩体的伤害；
- `A=0`（攻击归零）；
- 完全被重定向或完全被免疫承接，本体未承担任何后果的伤害；
- 掩体只承接耐久损失但未击破时的该次伤害（对本体无 HP 后果）。

有效伤害口径的消费方示例（都引用本条，不再自定）：

- T3 石化的被动解除与“尘世之锁”（见 T3/T7 v0.3）；
- G5 小昔涟阶段的追忆：全地图任一攻击满足本节有效伤害口径即登记基础战斗类别；小昔涟
  作为攻击者或有效受伤目标时，再登记一次亲历加成（见 G5 v0.4 §三）；
- 需要“受到伤害后解除 / 升级”的各类护盾与状态。

实现时在伤害流水线末尾统一打 `effective_damage=true/false` 标记，供各条件钩子读取。

### 6.7a G2 终曲 `shared_post_mitigation`

G2 v0.3 终曲只重新分配即将进入 HP 的最终整数伤害，不重新计算 A/H：

- 原目标完成护甲、掩体、防御与固定减伤后得到 `H0`；按 G2 RFC 的共享比例抽取 S；
- S 使用 G2 RFC 明文 `floor`，是 §6.2 公共 half-up 规则的局部例外；
- `H0-S` 留给原目标，S 在区域存活 actor 间整数均分；所有分配块合计必须等于 H0；
- 分配块标记 `shared_post_mitigation=true`，跳过属性/护甲/减伤/25% 下限并禁止再次共享；
- 原来源的 attacker、犯罪、击杀、PP、战果、案件与 `absolute_death` 标签保持不变；
- 各接收者的绝对免疫与死亡替代仍可处理自己的分配块，不把被免除伤害重新分给其他人。

### 6.8 死亡与 `absolute_death` 边界（2026-08-09 v0.3）

- **普通死亡**：进入正常死亡流程，可被普通死亡替代（替身、保险复活、死亡豁免）承接；
  死亡结算经由行动合同（[行动 v0.8](m9_action_system_rfc_v0.8.md) §4.4）把死亡玩家的
  **SP 清为 `0` 并移除公演队列资格**；复活/返场玩家从 SP=0 重新开始，不继承死亡前的
  就绪档位。
- **`absolute_death` 标签**：只由来源明确携带。携带该标签的致死结果**绕过普通死亡
  替代、死亡免疫与复活**——包括 T7 保险复活、G1 繁育等替代死亡结构、普通免死与
  返场扩展——**除非来源明文声明自己优先级更高**（任何来源都不能单靠 `absolute_death`
  被覆盖，必须是明文写出的更高优先来源）。
- `absolute_death` 不改变伤害值，也不提前于伤害流水线触发；它只决定死亡阶段的处理。
- **绝对死亡的往世层边界**：绝对死亡者进入终局状态 `absolute_dead`，**不进入往世层**，
  不能继续投注、转仓或提供魂援/援助；其 PP 冻结且不可支出，死亡前已经托管的赌注仍按
  终局结果正常结算，终分使用死者公式并计入死亡前已取得的援助收益。装备按普通死亡规则
  掉落。各来源不得只在局部 RFC 中另写不同的往世层待遇。
- **G5 小昔涟普通致死替代**：`CYRENE` 的普通致死在进入普通死亡流程前改写为
  `CYRENE_HOMECOMING`；不建立击杀者、不触发 T7/往世层/死亡投注。`absolute_death` 跳过
  该替代。精确寿命、掉落和诞生语义见 G5 v0.4。
- **G5 因果闭合**：`CAUSAL_CLOSURE` 是 retreat，不是死亡；服从评分指针 v0.1 §4.1，
  不触发 T7 或往世层。
- **G2 光身/影身**：光身是玩家死亡锚点；光身致死按普通/绝对死亡处理，并先幂等清理
  影身/终曲区域。影身 HP 归零只触发 `SHADOW_DISSIPATED`，不触发 T7、往世层或玩家击杀；
  命中影身的 `absolute_death` 只保证代理身体消散，不能越过 actor 目标把光身判死。

## 七、统一行动收尾

任何已经授予的行动槽都必须进入同一个 finalization 入口，禁止状态分支通过提前返回偶然
跳过 T2。收尾拆成三层：

### 7.1 系统收尾：永远执行

- 标记行动槽已经结算；
- 消费本槽对应的震荡、压制等状态；
- 更新队列、来源、递归深度和每轮上限；
- 处理死亡、胜利与必要的全局检查；
- 写入 `resolution_kind`。

### 7.2 根行动收尾：仅真实执行根行动时

- 现有 `on_turn_end` 类钩子；
- 行动记录、犯罪、关注事件与自主行动奖励；
- 自愿放弃属于自主根行动；压制、单纯唤醒、自我怀疑转化、保持石化、`aid_rest`
  （§7.4）不属于。

### 7.3 演出收尾：仅实际演出时

- SP 重置；
- 即演 / 公演记录；
- 追演、魂援、诗篇等演出专属结算。

### 7.4 `aid_rest`：休整式收尾类别（2026-08-09 v0.3）

`aid_rest` 是一种**无根行动、无演出**的收尾类别，用于把系统授予的槽位“消费掉但不
执行任何主动内容”：

- 下一次**实际获得**的行动槽（标准行动或完整额外行动）被 `aid_rest` 消费；
- 来源标记在行动控制裁决器**之前**改写该槽，因此同槽上的压制、石化、震荡、睡眠与
  自我怀疑均不消费、不清除，保留到之后的合法槽位；`aid_rest` 不是控制，也不占控制位；
- 该槽**没有 T0 / T1 / 根行动**：不移动、不交互、不攻击、不即演、不公演，也不产生
  自主根行动对应的奖励与钩子；
- **系统收尾照常运行**：`slot_resolved=true`、`root_action_performed=false`、
  `resolution_kind=aid_rest`；关注、SP、递归深度与每轮上限按系统收尾更新；
- 结算后移除**来源明文指定为 `aid_rest`** 的待决标记。`aid_rest` 不得从“效果在下一槽
  结束”自动推导；例如 G5 微澜只在下一次实际槽位的系统收尾中到期，绝不把该槽改写成
  `aid_rest`。

首批来源只有 B4 的 T3 防御援助：成交后立即获得承受方绝对伤害免疫，直到上述
`aid_rest` 槽完成系统收尾；免疫令来袭 `H=0`，但不把攻击方 `A` 改为 0。若玩家在终局前
始终未再取得槽位，标记与免疫在终局清理。

每个行动槽至少显式记录：

| 字段 | 含义 |
|---|---|
| `slot_assigned` | 是否真实获得一个行动槽 |
| `slot_resolved` | 该行动槽是否完成系统收尾 |
| `root_action_performed` | 是否执行自主根行动 |
| `performance_performed` | 是否实际执行演出 |
| `voluntary_forfeit` | 是否由玩家主动放弃 |
| `resolution_kind` | `normal`、`suppressed`、`wake`、`wake_followup`、`terror`、`petrified_hold`、`forfeit`、`aid_rest`、`shadow_dissipated`、`terminal_song_conversion` 等 |

不得再由单一 `acted_this_round` 反推这些事实。

## 八、`ActionGrant` 行动授予合同

R3 队列不得只保存玩家 ID。每个标准行动、完整额外行动或局部子舞台行动都应携带授予
信封，最少包含：

| 字段 | 含义 |
|---|---|
| `actor_id` | 行动者 |
| `kind` | `standard`、`full_extra`、`restricted_followup` 或局部子舞台类型 |
| `source_id` | 明文授予该行动的规则来源 |
| `global_round` | 计算每人每轮上限 |
| `grant_id` / `parent_grant_id` | 追踪根授予和插入关系 |
| `depth` | 阻断完整额外行动递归 |
| `allow_instant` | 是否允许在该行动 T0 即演 |
| `allow_public` | 是否允许公演 |
| `refresh_limits` | 是否刷新关注、SP 等每轮限制 |

### 8.1 授予前的预检钩子（2026-08-09 v0.3，对齐行动 v0.8 §4.3）

每个 `ActionGrant` 在消费任何 SP、资源或把槽位标记为 `spent` **之前**执行合法性预检
（目标合法、作用域合法、当前状态允许等）：

- 预检失败：不创建 / 不消费槽位，SP 与资源保持原状；来源视为未成立，不占用每轮上限；
- 预检通过：才建立槽位并进入结算；此后抵抗、未命中或控制消费照常扣减。

### 8.2 完整额外行动的确定性仲裁钩子（2026-08-09 v0.3，对齐行动 v0.8 §3.2.8）

同一玩家同一全局轮次多个完整额外行动候选同时成立时，按确定性事件序列仲裁：

- 先成立者得之（事件结算先后决定登记顺序）；
- 完全同一父事件内的同时候选，优先级固定为
  **T4「或跃在渊」 > G5「地火」之诗 > G4 负世主动燃尽**；
- 落选者整体丢弃，不部分保留、不后延、不结转。

本钩子由行动 v0.8 定义，结算合同在此登记为强制实现点。

完整额外行动统一遵守：

- 只由正面白名单 `source_id` 授予；
- 同一玩家每个全局轮次至多一个；
- 来源结算后立即插入；
- 深度至多 `1`，不能继续产生完整额外行动；
- `allow_instant=true`、`allow_public=false`、`refresh_limits=false`；
- 若被压制、睡眠或其他控制消费，该额外行动直接损失，不重新排队。

### 8.3 `restricted_followup` 受限追加授予

`restricted_followup` 是显式带权限位的第二个根行动载体，不等于追演，也不取得完整额外
行动权限：

- 派发后先运行死亡/离场与控制预检；没有玩家选择型 T0，不允许即演、公演、换装宣言或
  其他 T0 能力；
- 只开放来源写明的根行动集合，然后执行根行动收尾与系统收尾，因此它属于所有“下一次
  实际 ActionGrant”生命周期的消费点；
- `depth=1`、`refresh_limits=false`，禁止派生 `full_extra`、另一个
  `restricted_followup` 或追演；
- 第一批唯一来源为 G1 完全燃烧，每轮至多一次，权限只有 `move` / `attack`；
- 若压制等控制消费该授予，按对应 `resolution_kind` 收尾，来源不补发。

## 九、旧入口的迁移分类

| 旧来源 | M9 目标身份 | 后续批次 |
|---|---|---|
| T4「或跃在渊」 | 一个完整额外行动 | B1 冻结时序 |
| T5 谱面 / FC | 不迁入 M9；原槽位转为 G0 | 退役登记 |
| T2 犯罪 / 警觉 | 关注或 SP 事件，不授予完整行动 | B1 |
| G4 主动救世 | 删除额外行动；转折后令 SP=2 | B1 / B2 |
| 响应窗口 | 反应步骤，不进入全局行动队列 | B1 |
| G7 唤醒收益 | 在唤醒槽内结算受限衔接 | B1 |
| G2 普通影身 | 独立 actor 的代理标准槽；不是 `full_extra`、副舞台或第二玩家 | G2 v0.3 |
| G3 内部屏障 | 副舞台局部步骤 | B3 |
| G6 插入式笑话 | 根行动模板替换，不是额外行动 | B1 / B2 |

通用 `pending_extra_turns` 应在实现批次退役；每个来源改用带 `source_id` 的授予 API。

## 十、实现与验证边界

本 RFC 完成的是设计冻结，不授权直接修改 `v2exp`。后续原型至少要覆盖：

1. 控制裁决顺序、同级不叠加和结构状态保留（含流放返回位置）；
2. 压制消费标准 / 完整额外行动，并且仍执行系统收尾；
3. `A=0` 短路、`25%` 下限、易伤和虚弱所在阶段；
4. `DIRECT_DAMAGE` 跳过目标侧防御但仍被明文承接拦截、仍走伤害 / 关注 / 死亡流程；
5. 掩体破坏不溢出、离开地点后移除；
6. `ActionGrant` 来源白名单、每轮上限和深度阻断，以及 §8.1 预检钩子与 §8.2 仲裁钩子；
7. 统一有效伤害口径在所有消费方之间一致；
8. 普通死亡清 SP/队列与 `absolute_death` 绕过的边界；
9. 所有行动结果都进入公共 finalization，且三类钩子不串线；
10. legacy、`v2exp` 和未来 M9 实验 profile 不互相泄漏。

B1 可以在本合同上逐项处理 T4、G4、T2、G6 和 G7，并登记 T5 的 M9 退役；G2 v0.3 的代理
actor、终曲共享与压制例外由其独立 RFC 承接，G3/G5 的覆盖层边界继续服从各自当前合同。
通过纸面模型、合同测试和运行时验证前，不把本文件改写进 V2 玩家手册。
