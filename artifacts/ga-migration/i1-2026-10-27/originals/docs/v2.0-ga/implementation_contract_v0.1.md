# V2.0-GA 实施合同 v0.1

> 日期：2026-10-27。状态：I0参数与公共动作/效果/事件接口子批已完成；游戏运行链路进入I1。
> 用户继续授权破坏性迁移；目标是一个 GA 运行规则集。既有未提交工作、模型与实验记录保留。
> 玩法权威：[DEC-001～050](README.md#已决记录2026-10-26)与各 RFC；
> 首轮数值：[手册 §17 N0](manual_draft_v0.1.md#十七首轮数值表-n02026-10-26)。
> 本合同规定实现边界和验收，不增加新的技能、数值版本或长期运行 profile。

## 1. 是否可以开始

可以。十四人机制、行动/防御/死亡/全局法则和首轮数值已足够开展实现。OPEN-001 余下的
实战校准依赖 GA 引擎，不能继续用旧 M9 跑分代替；OPEN-009 转入接口与场景实现，
OPEN-010 转入单一规则迁移。没有必要先证明十四人胜率接近才写第一批代码。

当前机器上的运行事实仍是：`config/game_config.json` 默认 legacy；`engine/experiments.py`
保有 legacy、m1～m6、v2exp、m9-rfc 等入口；GA 尚未挂入正式入口。本合同的“准备完成”
不表示 GA 可以启动或已经兼容旧模型。

## 2. 迁移边界与保全

- 允许重写、删除被替代的规则和测试，允许改变数据结构、命令与 RL 空间；不承担旧规则
  继续可玩的兼容义务。测试是否保留取决于验证的行为，而不是旧文件名。
- 破坏性更新针对已退役的规则，不等于丢弃工作区。开工前记录 HEAD、状态和本批目标文件
  的改动；对将覆盖的已修改文件保存补丁，对将覆盖的未跟踪文件保存原件。散列清单仅能
  检测变化，不能代替可恢复副本。不要 reset、clean、覆盖式切分支或自动提交用户改动。
- 只保存本批将改文件的恢复材料，复用 Git 已有历史；不复制整个仓库，不复制模型目录。
  旧训练 checkpoint、轨迹和结果保留，并登记为旧 schema；不自动恢复训练。
- 每个修改批次最多五个文件；删除前检查直接引用、动态字符串引用、命令、测试和文档入口。
  规则退役记录写在本合同对应批次，不为每轮调参增加平行版本文档。
- 迁移期间可在 `engine/ga/` 建立尚未接正式入口的实现组件与测试夹具；这不注册第四个
  运行 profile。正式切换一次完成，最终默认入口只运行 GA；旧参数明确报退役，不能静默
  回退 legacy，也不能在 GA 缺能力时调用旧天赋补齐。
- `R0→R1→R2→R3→R4` 与 `T0→T1→T2` 保留；需要修改旧调度器、伤害分派或状态挂载时，
  改成通用接口。天赋交互由钩子/效果描述表达，不继续向核心增加 G0/G1 等具名分支。

## 3. 从现有代码复用什么

以下是 2026-10-27 源码核对后的迁移范围，不意味着对应模块整文件可以删除。

| 当前入口 | 复用价值 | GA 必须改动或移除的行为 |
|---|---|---|
| `engine/balance.py`、`data/balance.json` | 配置读取入口、缓存与重载 | 新 GA 必填键显式校验，不能用旧默认值掩盖缺键；配置只留一套活跃规则 |
| `engine/m9/action_system.py` | 行动授予 ID、额度、去重、父链 | FIFO 公演队列与旧授予来源改为先攻夺台、递补和完整收尾边界 |
| `engine/round_manager.py`、`engine/action_turn.py` | 生命周期入口、调度容器 | R2 不再齐射，R4 固定流水；T0 配额、首次出门、历史根动词与双计数统一接入 |
| `combat/damage_resolver.py`、`engine/m9/combat.py`、`resolution.py` | 来源归因、伤害结果与死亡接缝 | 重建单甲耐久计费/屏障/擦伤；退役 g5_anchor 等旧来源和旧 PP 奖励，不能只修改白名单 |
| `engine/m9/gate.py`、`talent_registry.py` | 稳定槽位、注册校验、幂等挂载思路 | 退役旧 G6TemplatePool、G2 独立影身/终曲区域等挂载；GA 注册不回退旧类 |
| `engine/action_enumerator.py`、`cli/validator.py` | 合法动作与执行前校验的共同入口 | 同地显形免 find，lock 属 T0，私人房间出门落锁；所有控制者读同一候选集 |
| `controllers/ai/` | 决策管道、候选复核、可见性与快照缓存 | 重写旧公演/形态适配，删除过时策略与地点假设；不无故改 Mixin 顺序或丢弃性能缓存 |
| `rl/action_spec.py`、`rl/schema.py` | 结构化动作与不兼容检查的思路 | 新动作/观察显式语义版本；现有 schema 主要比较维度，同维度但不同规则也必须拒绝 |
| `network/`、`cli/`、`game_logger` | 传输、控制器边界、日志 | 随新选择窗口同步协议载荷；只有改动此面时才安排对应端到端验收 |

最终规则组件以 `engine/ga/` 为接入边界，替换已迁出的 `engine/m9/` 运行规则。
在候选路径尚未接入口时，现有 M9 仍作为旧运行快照；不同时在两边补同一项新玩法。
文件改名与移除按调用关系逐批完成，不能提前宣告整个 M9 目录都是垃圾。

## 4. 共用实现合同

下列名称是接口约定，可在实现时采用等价类型；字段语义必须一致。`GameState` 继续是
唯一正式状态源；测试夹具可构造初始状态，生产控制器不能绕过验证器直接改状态。

| 对象 | 必需信息 | 责任与边界 |
|---|---|---|
| ActionRequest | 行动者、grant ID、阶段、动词、目标/参数、所选演出入口 | 仅表达选择；人类、脚本、BasicAI、RL 提交同一种语义 |
| ActionPlan | 预检结果、可用目标、费用明细、占用 T0/T1、随机需求 | 单步预检合法才扣费；复合根逐段预检，保留已结算结果 |
| EffectSpec | source、root ID、实际归因者、责任者、目标范围、伤害类型、命中/屏障/隔离权限 | 借刀可分离战果与犯罪归因；不能凭技能显示名推导穿盾或绝对死亡 |
| DefenseSpec | 稳定装备 ID、属性防御、当前/最大耐久、计费单价、屏障类型与适用范围 | 普通单甲、有限屏障、破碎整击承接分别描述；姿态不生成新耐久 |
| ResolutionRecord | A、屏障后余量、命中/擦伤、选甲、普通/附加磨甲、实际 HP 损失、濒死结果 | 是结算结果账本，不是第二个可写 GameState；伤害与破甲不能重复计分 |
| DomainEvent | 唯一 event ID、root ID、batch ID、实际轮、世界刻度、actor/target/owner、有效性 | 关注/PP/追忆/笑点/章节订阅同一份已落地事件；去重键按各自额度定义 |
| TimedEffect | 建立轮、首次可 tick 时点、剩余 tick 或待消费槽、刷新策略 | 建立轮不 tick 与明文短窗口例外显式标记；不把世界刻度当状态年龄 |
| ChoiceWindow | 接受者、可选项、是否真的获得 T0、待回答状态、合法性快照 | 献诗未回答不默认接受；礼盒没有可选 T0 时不能偷跑代拆或到期 |
| TerminalSnapshot | 存活者、章节、战果、实际 PP、终止原因、ruleset/schema、seed | 同批目标濒死完成才取快照；闭环展示重置不得清成绩；结果写入一次 |

事件的永久进展包括 HP、普通甲/有限盾/库存消耗、有限资格、章节与实际退场。只看本轮
HP 不变不能判定僵局；反过来，HP 的 1 点损失被无成本恢复且所有资源也回到原样，不能
因曾经出现过保底伤害就判定通过。R0 重置的轮内额度也不能冒充永久消耗。

### 4.1 一次结算的先后

```text
候选动作/目标预检
→ 合法单步支付资源并消费对应阶段
→ 解析目标/隔离/替身/免疫/命中与屏障权限
→ 屏障、有限护体、普通单甲减免与计费、实际HP损失
→ 本击附加磨甲与命中附带效果（按屏障/擦伤资格过滤）
→ absolute / 自身转折 / 保险 / 普通死亡
→ 同批目标完成；发布已确认事件并检查终局
→ 当前根的后续段（若仍合法且对局未终止）
→ T2追击/额度与完整收尾
→ 合法公演插队 / 未开始ExtraTurn / 后续标准槽
```

同批 AOE 按原子范围组处理；不同段不是一次整组伤害。某段触发终局后不继续打下一段。
普通甲破碎不把本击未挡伤害再加一次；绝对死亡只在真正致死时生效，繁育倒计时等明文
直接死亡入口单独登记。重复回调不能重复发奖、复活或终局结算。

### 4.2 数值装配

- N0 按通用、武器/甲/地点、行动/状态、计分/警察、各角色、诗篇映射成配置键；每个必填
  键都记录来源节号、单位、取整与范围。初值不继续散落在技能业务函数里。
- 参数校验至少覆盖：整数 HP/耐久、概率 0～1、非负价格、SP 上限2、弓箭5/10、T0一次、
  ExtraTurn每人每轮一次、光环3×2、初始Cost6、追忆上限12、毁伤上限9。
- 新规则缺键/坏类型启动失败并指出路径；不调用 `bget(default=旧值)` 冒充 GA 初值。
  `engine/balance.py` 的普通读取接口可复用；增加启动严格校验即可，不必重复造配置加载器。
- 正式切换前，N0 是设计权威；实现后配置是运行数值信源，手册从配置校验或装配。
  机制与数值修订都回写现有文档，日志记录 ruleset 与参数散列。

第二批的接口边界：

  不扣款、不消费随机数；合并付款者/账户后检查完整费用，并把HP保留线写入计划。
  执行器仍需复核快照并在正式状态事务中应用费用，后段失败不自动回滚前段。
- `EffectSpec`明示伤害类别、属性、数值屏障与隔离权限，区分实际施术者/战果/案底归属；
  source名称和任意payload不能自动授予权限。普通甲、有限池与破碎整击承接各有独立类型。
- `ResolutionRecord`检查实际HP损失、过量伤害、单甲磨损账与拦截回执；`EventLedger`
  要求同批每个声明目标都有结果，包括免疫目标，再一次发布。重复批次无新通知，冲突ID报错。
- 领取额度按实际入账量、根或无根系统批次、实际全局轮登记；重放返回0；旧轮不能补领。
  台账不持有第二份SP/钱包，不调用订阅回调；存活资格与天赋触发过滤仍由后续适配器处理。
- `TimedEffect`区分未来R4、任意槽和标准槽；`ChoiceWindow`区分未回答/已回答/到期。
  礼盒入口须显式设置`requires_t0_opportunity=True`；献诗可在收到时回答，绝不自动接受。
- `TerminalSnapshot`保存不可变逐人账目与实际PP余额；定格后不接受新事实或新奖励。
